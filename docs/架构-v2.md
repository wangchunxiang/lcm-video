## 1. 已确认决策

| 编号 | 决策 | 结论 | 理由 |
|---|---|---|---|
| 0.1 | 服务端框架 | NestJS 11（Express 适配器） | 需要框架强制分层，贴近 Spring Boot 的开发习惯 |
| 0.2 | 数据访问 | TypeORM 0.3（`@nestjs/typeorm`）+ `@ackplus/nest-crud` 的 `CrudService` | 实体 + 迁移是表结构的唯一真相源；CRUD 路由由装饰器生成，控制器不用逐条手写 |
| 0.3 | 运行时 | Node 24 + TypeScript | 现有环境，不改 |
| 0.4 | 数据库 | 在 `lcm-video` 新库从零建表，旧库 `lcm_video` 只作数据来源 | 旧库字段与索引无迁移版本、存在只写不读的列；重建成本低于逐个修补 |
| 0.5 | 站点 URL | 允许重新设计，旧地址不做 301 | SEO 不是要求，旧站直接下线；链接失效可接受 |
| 0.6 | 后台功能 | 以现有功能为参考，允许增删 | 目标是更好用，不追求一比一复刻 |
| 0.7 | 接口文档 | 不引入 OpenAPI/Swagger | 没有对外 API 消费方；`nest-crud` 自带的 swagger 依赖不启用 |
| 0.8 | 主键 | `BIGINT UNSIGNED`，JS 侧一律按 **string** 处理 | TypeORM 的 mysql 驱动默认 `bigNumberStrings`，BIGINT 天然是字符串，与 `nest-crud` 的 `BaseEntity.id: string` 一致，零断言；配套约定见「数据模型」 |
| 1.1 | 服务端编译 | 统一用 tsc（`nest build` / `nest start --watch`） | 一套配置、类型检查与产物同步；ReDoS 与 SWC 的元数据问题都避开 |
| 1.2 | 仓库形态 | turbo monorepo，包管理仍用 npm workspaces | 三个应用与两个包需要统一的任务编排与缓存，但不换包管理器 |
| 1.3 | 应用与包拆分 | `apps/{server,admin,web}` + `packages/{shared,api-client}`，单进程 Nest | 前后台与前台三个产物独立构建，共享契约走 `packages` |
| 1.4 | 配置装载 | `@nestjs/config` + 启动校验（class-validator 校验 env） | 缺变量启动即失败，配置可注入、测试可覆盖 |
| 1.5 | 严格度与 Lint | 保留 `strict` + `noUncheckedIndexedAccess`；ESLint 用 `recommendedTypeChecked` | 新代码零迁移成本，`no-floating-promises` 挡掉漏 await |
| 2.1 | 分层 | Controller → Service → Repository | 控制器只管入参出参；业务在 Service；Repository 由 TypeORM 注入，不再手写一层 |
| 2.2 | 模块划分 | 业务代码按表分目录；每个表模块 `TypeOrmModule.forFeature([实体])`；根模块只挂 Config 与 TypeOrm | 表结构稳定，功能往表目录里挂，不会出现无主代码 |
| 2.3 | 响应信封 | 全局 `ResponseInterceptor` 统一包 `{code,msg,data}`，`@Raw()` 标记例外 | 默认正确、例外显式，避免上百处手写 |
| 2.4 | 错误码 | `0` 成功、`1` 通用失败、`100401` 登录过期、`100403` 无权限、`100500` 服务端异常 | 默认只回 `1` + 可展示的 `msg`；只有前端必须分支的情况才用专用码 |
| 2.5 | 输入校验 | class-validator + class-transformer，全局 `ValidationPipe`（`whitelist` + `transform`） | 与 `nest-crud` / TypeORM 同一生态；DTO 即类，装饰器与字段贴在一起 |
| 2.6 | 列表与分页 | 直接用 `nest-crud` 的原生协议：`data = { items, total }`，请求参数 `take` / `skip` | 再包一层 `{list,pageNum,pageSize,totalPages}` 只是把同一个数字换个名字，前后端都要多写转换 |
| 2.7 | 目录结构 | `modules/` 下一目录一张表；无表功能（采集引擎、封面体检、广告识别）挂进使用它的模块目录；`portal/`（前台接口）与 `health/`（探活）不拥有表，单独成目录 | 一张表一个稳定位置，功能向下挂；不设顶层 `jobs/`，避免 `modules → jobs → modules` 来回引用 |
| 2.8 | 命名约定 | 目录名 = 表名去 `lcm_` 前缀的 kebab 形式；实体类 `XxxEntity`；DTO 文件名 `create-xxx.dto.ts` / `update-xxx.dto.ts` / `xxx-response.dto.ts` | 目录名与表名一一对应，找代码时从表名直达 |
| 2.9 | 表的默认接口 | REST，由 `@Crud()` 生成；语义缺口（按条件取唯一一条、取全量）补自定义路由 | 调用方只有自家后台，但它给的列表/分页/筛选查询参数比我们手写的更省代码 |
| 3.5 | 数据库变更策略 | 三类：可加（新表/可空新列/新索引）、需评估（改类型/缩长度/加唯一约束/删列）、禁止（连库手改结构、绕过迁移的 SQL、改历史迁移） | 旧库烂在没有规矩；实体与迁移是唯一真相源，一切变更留成迁移文件 |
| 3.6 | 连接与事务 | 单个 `DataSource`；事务用 `dataSource.transaction(...)`；采集**每页一个事务**，HTTP 请求在事务外 | 整任务一个事务不可行（全量几万条，失败全回滚）；每页提交让续采从 `last_page` 继续 |
| 3.4 | 裸 SQL 的落点 | 写在用到它的 Service 里，不建单独的 raw 文件 | 一条 SQL 只服务一个业务场景，就近维护比集中更直接 |
| 4.1 | 前台渲染 | Vue 3 SPA（Vite 独立应用 `apps/web`），不做 SSR | SEO 不是要求；与后台同一套技术心智，`themes/` 的 23 个 Liquid 与 `theme.ts` 的 filter 全部退场 |
| 4.2 | 桌面与移动 | 一套响应式，不维护两套模板树 | 同一套组件 + 断点即可覆盖（6 列变 2 列、header 收抽屉） |
| 4.3 | 前台路由 | Vue Router 定义页面；筛选与播放位置全部走 query | 便于分享与刷新保持，服务端不需要解析这些路径 |
| 4.4 | 旧 URL | 不做 301，旧站直接下线 | 不追求 SEO 迁移，没有必须保住的外链 |
| 4.5 | sitemap / robots | 不做 | 同 4.4 |
| 4.6 | 前端构建 | `apps/web` 与 `apps/admin` 各自 Vite 构建，产物由 server 静态托管 | 两个独立应用，互不打包 |
| 4.7 | 客户端交互 | Vue Router + 统一请求封装；换线路/换集用 `replace` | 不写浏览器历史，后退键从播放页直接回详情页 |
| 4.8 | 页面数据契约 | `/api/site/*` 返回 `PageData` DTO | 前台只消费 JSON，服务端不再渲染 HTML |
| 4.9 | 前台 UI 库 | 复用 Element Plus（按需导入、暗色主题） | 与后台一致，不引入第二套组件库；卡片墙等仍自写 CSS |
| 5.1 | 后台前端框架 | 继续 Vue 3 + Element Plus | 与前台同一套心智；换 React 等于重写 15 个页面，收益不足以抵消成本 |
| 5.2 | 后台前端结构 | 请求层收口 `request.ts` + `ProTable`/`ProForm` 公共组件，筛选与分页同步到 URL query | 15 个页面重复的表格/分页/错误处理收到一处；表单与接口共用同一份 DTO 类型 |
| 5.3 | 鉴权与会话 | 沿用 JWT，不加刷新令牌；token 存 localStorage，`100401` 清 token 跳登录 | 单人后台、无富文本入口，XSS 面小；改 cookie 要连带处理 CSRF |
| 5.4 | 文件上传 | 不提供上传功能 | 图片一律用外链 URL；站点 logo/favicon 内置在 `apps/web` 静态资源 |
| 6.1 | 采集进程 | 与后端服务同进程，代码放 `modules/collect/` | 单机；将来要拆时整目录搬成第二个 entry |
| 6.2 | 调度实现 | `@nestjs/schedule` 每 30 秒轮询任务表，用带条件的 `update` 抢锁 | 同一个任务只能被一个进程改成「运行中」，多实例也不会重复跑 |
| 6.3 | 任务队列 | 不引入 | 单进程，队列解决的是削峰与跨进程分发 |
| 6.4 | 日志 | pino（`nestjs-pino`）+ 请求 ID；错误响应带 `reqId`，慢请求记 warn | 排障时按 id 串起一次请求的全部日志；JSON 行可按字段过滤 |
| 7.1 | 测试策略 | 纯函数单测（`npm test`）+ 真库 e2e（`npm run test:e2e`，supertest + `Test.createTestingModule`）+ 采集解析/合并的真库测试 | 集成测试不走真实端口；只给最怕回归的地方接真库 |
| 7.2 | 质量门 | `npm run check` = typecheck + lint + test + build，手工执行；e2e 单独 `npm run test:e2e`（需要 MySQL，不进 check）。暂不配 CI，等部署形态（7.3）定下来再接 runner | 单人项目，CI 的守门价值要等有 runner 才成立 |
| 7.3 | 部署形态 | 单进程同时提供 API 与静态页面：后台挂 `/admin/`、前台挂 `/`，构建产物存在时由服务端托管（history 路由回落到 `index.html`）；部署用 Docker 镜像或 PM2 二选一 | 单机规模，省掉 nginx 与跨域配置；容器编排的复杂度换不来收益 |
| 8.1 | API 版本化 | 不加 `/v1` | 没有第三方消费方 |
| 8.2 | 时间序列化 | 统一 ISO 8601 字符串，由拦截器把 `Date` 转成字符串 | 避免同一接口有时字符串有时对象 |
| 8.4 | 文档与注释语言 | 中文 | 现状如此 |

## 2. 由决策推出的约束

### 构建与仓库

NestJS 依赖装饰器元数据（`emitDecoratorMetadata`），Node 24 的类型剥离与 esbuild/tsx 都不提供，必须编译。

- turbo 任务：`build` 依赖 `^build`（`shared` 先于 `server`），`dev` 常驻；根 `npm run check` 依次跑 typecheck / lint / test / build。
- `tsconfig.base.json` 放公共编译选项，各包自己的 `tsconfig.json` 只写差异（`server` 额外开 `experimentalDecorators`、`emitDecoratorMetadata`、`outDir`）。
- 服务端产物在 `dist/`，启动点是编译后的 JS；`Dockerfile` 与 `ecosystem.config.cjs` 都是「先 build、再运行 dist」。
- `packages/shared` 只放纯函数与 DTO 类型（无装饰器、无 IO），编成 CJS + `.d.ts` 供两边消费。
- `packages/api-client` 由接口清单生成/手写，调用 `nest-crud` 的查询协议；不引入运行时依赖。

### 数据模型

- 实体放 `modules/<表>/<表>.entity.ts`，用 `@Entity('lcm_xxx')` 显式指定表名；列名用 `@Column({ name: 'snake_case' })` 对齐库里的下划线命名。
- 所有实体继承 `AppBaseEntity`（`common/crud/app-base.entity.ts`）：`id`（BIGINT UNSIGNED 自增）、`createdAt`、`updatedAt`；`deletedAt` 是无装饰器的幻影字段，只为满足 `nest-crud` 的类型约束，所有控制器统一 `softDelete: false`。
- **主键与引用列一律 `BIGINT UNSIGNED`，JS 侧是字符串**：不做算术、不与数字用 `===`、排序交给数据库。例外只有三类外部标识，保持 `VARCHAR(50)`：`lcm_collect_source_category.source_type_id`、`source_type_pid`、`lcm_vod_play.source_vod_id`（它们是源站的 id，可能与本站主键不同构，空串表示"无"）。
- 表结构的唯一真相源是实体 + `apps/server/src/database/migrations/`。首个迁移是 baseline：按实体从零建表（表注释、字段注释都写进迁移 SQL），并手工补 `CHECK` 约束（`ck_status_mapped` 等 TypeORM 表达不了的部分）。
- **建表自动化**：`config/typeorm.config.ts` 里 `synchronize: false` + `migrationsRun: true`，服务端启动时自动执行未应用的迁移——空库直接建出全部表，已建过的库只跳过。早期 `db:init` 建的老库（有表、没有 `migrations` 表）由 `database/schema-bootstrap.ts` 在启动时登记为已迁移，不会重复建表。
- **实体与迁移用显式清单**（`database/entities.ts`、`database/migrations/index.ts`），不用 `entities: ['**/*.entity.ts']` 这种 glob：glob 在运行时要 `require` 文件，e2e（vitest + swc）下会 require 到 `.ts`，Node 的类型擦除不支持装饰器。新增实体 / 迁移忘了登记会被 `database/entities.test.ts` 挡下。
- 种子 SQL 放 `apps/server/src/database/seeds/`（`lcm_admin_user` / `lcm_category` / `lcm_setting`），由 `npm run db:seed`（`src/database/seed.ts`）导入；内容待从真实库校对。开发期重建库用 `npm run db:reset`（DROP 全表后按迁移重建，需 `--force`），单独执行迁移用 `npm run db:migrate`。
- `vod.cover_host` 是普通列（不是生成列），索引保留，由业务代码在写封面时维护。
- 不建物理外键：表间关联靠列 + 索引 + 应用层保证。
- `created_at` / `updated_at` 由 `@CreateDateColumn` / `@UpdateDateColumn` 维护，DDL 上是 `DEFAULT CURRENT_TIMESTAMP(6)` 与 `ON UPDATE CURRENT_TIMESTAMP(6)`；**原生 SQL** 更新行时必须自己补 `updated_at = NOW()`。
- 裸 SQL 用 `dataSource.query(...)` / `repository.query(...)`，参数走占位符数组，不拼字符串；方法上注释说明为什么 QueryBuilder 表达不了。
- 事务写在 Service 方法内，不跨 HTTP 请求；采集按「一页」提交（默认 100 条），不按整个任务提交。
- 网络请求（请求源站、下载页面）一律在事务外；事务内只做写库。

### 对外

- URL 可以重新设计；旧地址不做 301，切换时旧站直接下线。
- 后台功能允许增删与重新设计；盘点文档只用于提示「别漏掉已有能力」，不作为验收标准。

### 契约

- 成功：`{ code: 0, msg: 'ok', data }`。
- 失败：`{ code: 1, msg, data: null }`；需要前端分支时改用专用码（`100401` 登录过期、`100403` 无权限、`100500` 服务端异常）。
- 前端判断：`code === 0` 成功；`code === 100401` 清 token 跳登录；其余直接把 `msg` 展示。
- JSON 接口的 HTTP 状态码固定 `200`，不承载语义；前台页面与静态资源不走信封。
- 信封由全局 `ResponseInterceptor` 生成，控制器只返回 `data`；例外用 `@Raw()` 标记（静态资源、NDJSON 流、文件下载）。
- 列表统一 `{ items, total }`，请求参数 `take` / `skip`（`take` 上限 100，超出按 100 处理；不分页取全量走自定义路由，上限 1000）。
- 筛选与排序用 `nest-crud` 的查询协议：`where` 为 JSON（操作符 `$eq $ne $gt $gte $lt $lte $like $iLike $in $notIn $between $isNull $isNotNull ...`），`order` 为 JSON（`{"sort":"DESC"}`）。**没有 `$cont`**，模糊匹配写 `$like: "%关键词%"`。
- 入参校验走全局 `ValidationPipe`（`whitelist: true`、`transform: true`、`forbidNonWhitelisted: true`），错误信息用 `exceptionFactory` 压成 `字段: 中文提示`。
- 唯一性与存在性在 Service 里预检（`findOne` / `count` 命中即抛 `BadRequestException`），并由实体的唯一索引兜底；不引入第三方校验器。预检与插入之间有竞态，撞唯一键时统一落成 `100500`。

### 目录与命名

```
apps/
├─ server/                         NestJS：后台接口、前台接口、采集任务
│  ├─ src/
│  │  ├─ main.ts  app.module.ts
│  │  ├─ common/                   与业务无关的横切件
│  │  │  ├─ crud/                  AppBaseEntity、CrudService 封装
│  │  │  ├─ decorators/            @Public @CurrentUser @Raw
│  │  │  ├─ filters/               全局异常出口
│  │  │  ├─ guards/                JWT 守卫
│  │  │  ├─ http/                  信封与错误码
│  │  │  ├─ interceptors/          信封、时间序列化
│  │  │  ├─ pipes/                 校验管道
│  │  │  └─ security/              jwt、登录锁定、密码哈希
│  │  ├─ config/                   configuration.ts（配置快照）validation.schema.ts（启动校验）
│  │  │                            typeorm.config.ts（连接参数，Nest 与 CLI 共用）
│  │  ├─ database/                 data-source.ts  migrate.ts  seed.ts  reset.ts
│  │  │                            schema-bootstrap.ts（老库登记）  migrations/  seeds/
│  │  ├─ modules/                  业务：一个目录 = 一张表，无表功能挂到用它的模块下
│  │  │  ├─ <表>/                  <表>.module.ts  controller.ts  service.ts  entity.ts
│  │  │  │                         dto/<表>.dto.ts
│  │  │  ├─ collect/               采集引擎（无表）：classes client parser merge writer runner scheduler
│  │  │  ├─ cover-check/           封面体检：controller/service + probe repair
│  │  │  ├─ ad-feature/            广告识别：controller/service + analyze skip
│  │  │  ├─ portal/                前台接口：不拥有表，只做只读聚合
│  │  │  └─ health/                探活：不拥有表，只读数据库与进程状态
│  └─ test/                        集成测试（e2e）预留，单测与源码同目录
├─ admin/                          Vue 3 + Element Plus（后台）
└─ web/                            Vue 3 + Element Plus（前台 SPA）
packages/
├─ shared/                         纯函数与契约：enums/ 枚举、types/ 纯类型
└─ api-client/                     调用封装（查询协议、错误码处理）
```

- 一张表一个 controller 文件，所有接口写进这一个文件，不按用途拆文件；同目录平铺 `controller.ts` / `service.ts` / `module.ts` / `entity.ts`，不为单个文件再建子目录。
- `<表>.module.ts` 只做注册：`imports: [TypeOrmModule.forFeature([XxxEntity])]` + `controllers` + `providers`；要给别的表用它的 service 时在这里 `exports`。
- 新增接口的归属看它主要改哪张表；同时改多张表时归主表，其余表通过对方 service 调用。
- 无表的后台任务（采集引擎、封面体检、广告识别）不单独开顶层 `jobs/`，而是作为实现文件放进使用它的模块目录，避免 `modules → jobs → modules` 的来回引用。
- 除 `portal` 与 `health` 外，`src/` 顶层不得再新增非表的代码集合。
- DTO 一律放模块的 `dto/<表>.dto.ts`：`@AppCrud` 用的 create / update 与自定义动作路由的入参都写在同一文件，控制器不内联 DTO 类；只带 `id` / `sourceId` 的动作入参用 `common/dto/id.dto.ts` 的 `IdDTO` / `SourceIdDTO`。

### 表的默认接口

`@AppCrud({ entity, path: 'api/admin/<表>', dto })` 生成标准 REST 路由。项目默认值集中在 `common/crud/app-crud.decorator.ts`：不软删（`softDelete: false`，`restore` / `deleteFromTrash` 四条回收站路由随之自动关闭）、`maxPerPage: 100`、关掉 `createMany` 与 `reorder`；控制器里只写 `entity` / `path` / `dto` 等差异项。

| 动作 | 方法与路径 | 语义 |
|---|---|---|
| 列表 | `GET /api/admin/<表>` | 支持 `where` / `order` / `take` / `skip` / `select` / `relations`；返回 `{ items, total }` |
| 单条 | `GET /api/admin/<表>/:id` | 按主键取 |
| 新建 | `POST /api/admin/<表>` | 返回创建后的实体 |
| 更新 | `PUT /api/admin/<表>/:id` | 局部更新 |
| 删除 | `DELETE /api/admin/<表>/:id` | 硬删除（`softDelete: false`） |

补充路由（`nest-crud` 不覆盖的语义，写在同一个 controller 里）：

| 动作 | 路径 | 语义 |
|---|---|---|
| 按条件取唯一 | `GET /api/admin/<表>/one?...` | 命中 0 条报「不存在」，≥2 条报「条件不唯一」 |
| 取全量 | `GET /api/admin/<表>/all?...` | 数组，上限 1000 |

- 批量操作、跨表联动写在主表 controller 里，路径同样是 `/api/admin/<表>/<动作>`，不新建无表目录。
- 内部表（`setting`、`admin-user`、`collect-task-log-detail` 等）同样按上表开；`admin-user` 的响应 DTO 不含密码字段。
- NDJSON 流走 `@Raw()`，不受信封约束。

### 前台

前台是与后台同构的独立 SPA，服务端不再渲染任何 HTML。

```
apps/web      Vue 3 + Vue Router + Element Plus（按需导入、暗色主题）
apps/server   /api/site/* 公开 JSON；其余路径回落 index.html
```

- 页面与路由：`/` 首页、`/today` 今日更新、`/category/:alias` 分类列表、`/vod/:id` 详情、`/play/:id` 播放、`/search` 搜索。
- 筛选与播放位置全部放 query：`/category/:alias?type=&year=&sort=&page=`、`/play/:id?line=<lcm_play_line.id>&ep=<1 基集数>`。
- 列表分页参数在前台用 `page`，由 `apps/web` 的请求层换算成 `skip = (page - 1) * take`；后台 `ProTable` 直接传 `take`/`skip`。
- 换集与换线路都用 `router.replace`：不写浏览器历史，后退键从播放页直接回到详情页。
- 静态回落与 `/api` 分流由服务端中间件完成；v1 的 `themes/` 目录已删除，品牌资源（favicon、icon、logo、占位图）移到 `apps/web/public/`。
- Element Plus 通过 `element-plus/theme-chalk/dark/css-vars.css` 启用暗色，再用站点色板覆盖 `--el-color-*` 变量。
