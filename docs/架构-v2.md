## 1. 已确认决策

| 编号 | 决策 | 结论 | 理由 |
|---|---|---|---|
| 0.1 | 服务端框架 | NestJS 11（Express 适配器） | 需要框架强制分层，贴近 Spring Boot 的开发习惯 |
| 0.2 | 数据访问 | Prisma 6（当前 6.19.3） | `schema.prisma` 作为表结构与迁移的唯一真相源 |
| 0.3 | 运行时 | Node 24 + TypeScript | 现有环境，不改 |
| 0.4 | 数据库 | 在 `lcm-video` 新库从零建表，旧库 `lcm_video` 只作数据来源 | 旧库字段与索引无迁移版本、存在只写不读的列；重建成本低于逐个修补 |
| 0.5 | 站点 URL | 允许重新设计，旧地址不做 301 | SEO 不是要求，旧站直接下线；链接失效可接受 |
| 0.6 | 后台功能 | 以现有功能为参考，允许增删 | 目标是更好用，不追求一比一复刻 |
| 0.7 | 接口文档 | 不引入 OpenAPI/Swagger | 没有对外 API 消费方，文档用 Markdown 维护即可 |
| 1.1 | 服务端编译 | 统一用 tsc（`nest build` / `nest start --watch`） | 一套配置、类型检查与产物同步；本项目规模小，增量重启足够快 |
| 1.2 | 包管理与工作区 | 保留 npm workspaces | 包少、无跨包构建编排，换 pnpm 收益不抵迁移成本 |
| 1.3 | 仓库与应用拆分 | 单进程 Nest，代码按表分目录（见 2.7） | 单机单人维护，共享 service 与 PageData 零成本；边界靠 import 规则约束 |
| 1.4 | 配置装载 | `@nestjs/config` + 启动校验（校验库与 2.5 统一后再定） | 缺变量启动即失败，配置可注入、测试可覆盖 |
| 1.5 | 严格度与 Lint | 保留 `strict` + `noUncheckedIndexedAccess`；ESLint 用 `recommendedTypeChecked` | 新代码零迁移成本，`no-floating-promises` 挡掉漏 await |
| 2.1 | 分层 | 三层：Controller → Service → PrismaService，不设 Repository | Prisma Client 已是数据访问抽象，再加一层只是改名 |
| 2.2 | 模块划分 | 业务代码按表分目录；Nest 模块只留根模块 + Prisma/Config 两个全局模块 | 表结构稳定，功能往表目录里挂，不会出现无主代码 |
| 2.3 | 响应信封 | 全局 `ResponseInterceptor` 统一包 `{code,msg,data}`，`@Raw()` 标记例外 | 默认正确、例外显式，避免 95 处手写 |
| 2.4 | 错误码 | `0` 成功、`1` 通用失败、`100401` 登录过期、`100403` 无权限、`100500` 服务端异常 | 默认只回 `1` + 可展示的 `msg`；只有前端必须分支的情况才用专用码 |
| 2.5 | 输入校验 | zod，env 与接口共用同一套 schema | 一次写出运行时校验与 TS 类型，schema 可下发到 `packages/shared` 供后台表单复用 |
| 2.6 | 分页 | 统一 `Page<T> = {list,total,pageNum,pageSize,totalPages}`，请求参数同名 | 一处定义，前后台共用，避免参数名转换 |
| 2.7 | 目录结构 | `modules/` 下一目录一张表；`portal/`（前台接口）与 `jobs/`（后台任务）与 `modules/` 平级 | 一张表一个稳定位置，功能向下挂；无表代码不污染 `modules` |
| 2.8 | 命名约定 | 目录名取 Prisma model 的 kebab；DTO 导出名 `XxxDTO`；一表一个 controller 文件 | 目录名与 schema 一致，改名一次同步 |
| 2.9 | 表的默认接口 | 每表六个端点，全部 `POST`，路径 `/api/admin/<表>/<动作>` | 调用方只有自家后台，REST 的收益用不上，而 query 序列化与路由顺序的成本天天在付 |
| 4.1 | 前台渲染 | Vue 3 SPA（Vite 独立应用 `apps/web`），不做 SSR | SEO 不是要求；与后台同一套技术心智，`themes/` 的 23 个 Liquid 与 `theme.ts` 的 filter 全部退场 |
| 4.2 | 桌面与移动 | 一套响应式，不维护两套模板树 | 同一套组件 + 断点即可覆盖（6 列变 2 列、header 收抽屉） |
| 4.3 | 前台路由 | Vue Router 定义页面；筛选与播放位置全部走 query | 便于分享与刷新保持，服务端不需要解析这些路径 |
| 4.4 | 旧 URL | 不做 301，旧站直接下线 | 不追求 SEO 迁移，没有必须保住的外链 |
| 4.5 | sitemap / robots | 不做 | 同 4.4 |
| 4.6 | 前端构建 | `apps/web` 与 `apps/admin` 各自 Vite 构建，产物由 server 静态托管 | 两个独立应用，互不打包 |
| 4.7 | 客户端交互 | Vue Router + 统一请求封装；换线路/换集用 `replace` | 不写浏览器历史，后退键从播放页直接回详情页 |
| 4.8 | 页面数据契约 | `/api/site/*` 返回 `PageData` DTO | 前台只消费 JSON，服务端不再渲染 HTML |
| 4.9 | 前台 UI 库 | 复用 Element Plus（按需导入、暗色主题） | 与后台一致，不引入第二套组件库；卡片墙等仍自写 CSS |
| 5.1 | 后台前端框架 | 继续 Vue 3 + Element Plus | 与前台同一套心智；换 React 等于重写 15 个页面，收益不足以抵消成本 |
| 5.4 | 文件上传 | 不提供上传功能 | 图片一律用外链 URL；站点 logo/favicon 内置在 `apps/web` 静态资源，`site_logo`/`site_favicon`/`upload_max_mb` 三个配置键删除 |
| 6.1 | 采集进程 | 与后端服务同进程，代码放 `jobs/collect/` | 单机；将来要拆时整目录搬成第二个 entry |
| 6.2 | 调度实现 | `@nestjs/schedule` 每 30 秒轮询任务表，用带条件的 `updateMany` 抢锁 | 同一个任务只能被一个进程改成「运行中」，多实例也不会重复跑 |
| 3.5 | 数据库变更策略 | 三类：可加（新表/可空新列/新索引）、需评估（改类型/缩长度/加唯一约束/删列）、禁止（连库手改结构、绕过迁移的 SQL、改历史迁移） | 旧库烂在没有规矩；`schema.prisma` 是唯一真相源，一切变更留成迁移文件 |
| 3.6 | 连接与事务 | 单 `PrismaClient`、单连接池；采集**每页一个事务**，HTTP 请求在事务外 | 整任务一个事务不可行（全量几万条，失败全回滚）；每页提交让续采从 `last_page` 继续 |
| 3.4 | 裸 SQL 的落点 | 写在用到它的 Service 里，不建单独的 raw 文件 | 一条 SQL 只服务一个业务场景，就近维护比集中更直接 |
| 5.2 | 后台前端结构 | 请求层收口 `request.ts` + `ProTable`/`ProForm` 公共组件，筛选与分页同步到 URL query | 15 个页面重复的表格/分页/错误处理收到一处；表单与接口共用同一份 zod schema |
| 5.3 | 鉴权与会话 | 沿用 JWT，不加刷新令牌；token 存 localStorage，`100401` 清 token 跳登录 | 单人后台、无富文本入口，XSS 面小；改 cookie 要连带处理 CSRF |
| 6.3 | 任务队列 | 不引入 | 单进程，队列解决的是削峰与跨进程分发 |
| 6.4 | 日志 | pino（`nestjs-pino`）+ 请求 ID；错误响应带 `reqId`，慢请求记 warn | 排障时按 id 串起一次请求的全部日志；JSON 行可按字段过滤 |
| 7.1 | 测试策略 | 纯函数单测 + `app.inject()` 集成（mock PrismaService）+ 采集解析/合并的真库测试 | inject 不起端口不碰网络，成本低；真库测试只给最怕回归的地方 |
| 7.2 | 质量门 | `npm run check` = typecheck + lint + test + build，手工执行，不配 CI | 单人项目，CI 的守门价值不存在 |
| 8.1 | API 版本化 | 不加 `/v1` | 没有第三方消费方 |
| 8.2 | 时间序列化 | 统一 ISO 8601 字符串，由拦截器把 Prisma 的 `Date` 转成字符串 | 避免同一接口有时字符串有时对象 |
| 8.4 | 文档与注释语言 | 中文 | 现状如此 |
## 2. 由决策推出的约束

### 构建

NestJS 依赖装饰器元数据（`emitDecoratorMetadata`），Node 24 的类型剥离与 esbuild/tsx 都不提供，必须编译。编译工具统一用 tsc，不引入 SWC。

- 产物在 `dist/`，启动点是编译后的 JS，不再 `node src/index.ts` 直跑。
- `Dockerfile` 与 `ecosystem.config.cjs` 改为「先 build、再运行 dist」。
- `apps/server` 需要独立的 `tsconfig.server.json`：开启 `experimentalDecorators`、`emitDecoratorMetadata`、`outDir`，关闭 `erasableSyntaxOnly`、`noEmit`、`allowImportingTsExtensions`、`verbatimModuleSyntax`；保留 `strict`、`noUncheckedIndexedAccess`、`skipLibCheck`，并加 `incremental`。

### 数据模型

- 表结构的唯一真相源是 `schema.prisma`；`packages/db/init.sql` 与 `packages/db/src/schema.ts` 退场。
- 结构变更走 `prisma migrate`：新库的首个迁移就是从零建表（`packages/db/prisma/migrations/`），此后只追加迁移，不重写历史。
- `vod.cover_host` 是普通列（不是生成列），索引保留，由业务代码在写封面时维护。
- 不建物理外键：表间关联靠列 + 索引 + 应用层保证。
- 裸 SQL 写在用到它的 Service 里，参数一律用 `$queryRaw` 模板插值，不拼字符串；对应的方法上用注释说明为什么 Prisma API 表达不了。
- 只有一个 `PrismaClient`（`PrismaService` 全局单例），单连接池，大小由 `DB_POOL_MAX` 控制。
- 事务写在 Service 方法内，不跨 HTTP 请求；采集按「一页」提交（默认 100 条），不按整个任务提交。
- 网络请求（请求源站、下载页面）一律在事务外；事务内只做写库。

### 对外

- URL 可以重新设计；旧地址不做 301，切换时旧站直接下线。
- 后台功能允许增删与重新设计；盘点文档只用于提示「别漏掉已有能力」，不作为验收标准。

### 工程约定

- 开发 `nest start --watch`（tsc 增量编译），构建 `nest build`，类型检查随构建完成。
- ESLint 用 `typescript-eslint` 的 `recommendedTypeChecked` 预设，加导入排序。
- 不启用 `consistent-type-imports`：它会把注入用的类改写成 `import type`，令装饰器元数据退化为 `Object`，直接导致依赖注入失败。

### 契约

- 成功：`{ code: 0, msg: 'ok', data }`。
- 失败：`{ code: 1, msg, data: null }`；需要前端分支时改用专用码（`100401` 登录过期、`100403` 无权限、`100500` 服务端异常）。
- 前端判断：`code === 0` 成功；`code === 100401` 清 token 跳登录；其余直接把 `msg` 展示。
- JSON 接口的 HTTP 状态码固定 `200`，不承载语义；前台页面与静态资源不走信封。
- 信封由全局 `ResponseInterceptor` 生成，控制器只返回 `data`；例外用 `@Raw()` 标记（前台 HTML、静态资源、NDJSON 流、文件下载）。
- 列表统一 `Page<T> = { list, total, pageNum, pageSize, totalPages }`，请求参数同名 `pageNum` / `pageSize`（默认 20，上限 100；前台按 `list_page_size` 覆盖）。
- 入参用 zod schema 校验，schema 放 `packages/shared`，后台表单复用同一份。

### 目录与命名

```
apps/server/src/
├─ main.ts
├─ app.module.ts
├─ common/                        interceptor/ filter/ pipe/ decorator/ paging/
├─ config/                        config.module.ts  env.schema.ts
├─ prisma/                        prisma.module.ts  prisma.service.ts
├─ modules/                       业务：一个目录 = 一张表
│  ├─ category/                   category.controller.ts  category.service.ts  category.module.ts  dto/category.ts
│  ├─ vod/  vod-play/  play-line/
│  ├─ collect-source/  collect-source-category/  source-rule/
│  ├─ collect-task/  collect-log/  ad-feature/
│  ├─ admin-user/  setting/  cover-check/  vod-merge-ignore/
├─ portal/                        前台接口：不拥有表，只做只读聚合
└─ jobs/                          后台任务：不由请求驱动
   └─ collect/                    client  parser  writer  runner  scheduler
```

- 表目录名取 Prisma model 的 kebab 形式（`VodPlay` → `vod-play`），与 `schema.prisma` 保持一致。
- 一张表一个 controller 文件，所有接口写进这一个文件，不按用途拆文件。同目录平铺 `<表>.controller.ts` / `<表>.service.ts` / `<表>.module.ts`，不为单个文件再建 `controller/`、`service/` 子目录；DTO 仍放 `dto/`。
- `<表>.module.ts` 只做注册：`controllers` + `providers`，要给别的表用它的 service 时在这里 `exports`；它不含任何逻辑。
- DTO 文件为 `dto/<表名>.ts`，导出名 `XxxDTO`；zod schema 与推导类型同名（`export const XxxDTO = z.object(...)` + `export type XxxDTO = z.infer<typeof XxxDTO>`）。
- 新增接口的归属看它主要改哪张表；同时改多张表时归主表，其余表通过对方 service 调用。
- 除 `portal` 与 `jobs` 外，`src/` 顶层不得再新增非表的代码集合。

### 表的默认接口

每张表在 `<表>.controller.ts` 里提供六个端点，全部 `POST`，路径为 `/api/admin/<表>/<动作>`（`<表>` 与目录名、Prisma model 同名，路径前缀由后端统一加）：

| 动作 | 路径 | 入参 | 语义 |
|---|---|---|---|
| 新增 | `/create` | 创建 DTO | 返回创建后的记录 |
| 修改 | `/update` | `{ id, ...变更字段 }` | 只更新传入字段，返回更新后的记录 |
| 删除 | `/delete` | `{ ids: number[] }` | 单条也传数组，返回受影响条数 |
| 单条 | `/get` | 任意查询条件 | 命中 0 条或 2 条以上均报错（「不存在」/「条件不唯一」），恰好 1 条才返回 |
| 分页 | `/page` | `{ pageNum, pageSize, ...条件 }` | `Page<T>` |
| 全部 | `/all` | 可选条件 | 数组，上限 1000 |

- `get` 用 `findMany({ take: 2 })` 判定唯一性，不用 `findFirst`。
- 附加接口（批量操作、跨表联动）写在主表 controller 里，路径同样为 `/api/admin/<表>/<动作>`，不新建无表目录。
- 内部表（`setting`、`admin-user`、`collect-log-detail` 等）同样开满六件套；`admin-user` 的输出 DTO 不含密码字段。
- 文件上传走 `multipart/form-data`，下载与 NDJSON 流走 `@Raw()`，两者不受上表约束。
### 前台

前台是与后台同构的独立 SPA，服务端不再渲染任何 HTML。

```
apps/web      Vue 3 + Vue Router + Element Plus（按需导入、暗色主题）
apps/server   /api/site/* 公开 JSON；其余路径回落 index.html
```

- 页面与路由：`/` 首页、`/today` 今日更新、`/category/:alias` 分类列表、`/vod/:id` 详情、`/play/:id` 播放、`/search` 搜索。
- 筛选与播放位置全部放 query：`/category/:alias?type=&year=&sort=&pageNum=`、`/play/:id?line=<lcm_play_line.id>&ep=<1 基集数>`。
- 换集与换线路都用 `router.replace`：不写浏览器历史，后退键从播放页直接回到详情页。
- 静态回落与 `/api` 分流由服务端中间件完成；`themes/` 目录在切换时整体删除。
- Element Plus 通过 `element-plus/theme-chalk/dark/css-vars.css` 启用暗色，再用站点色板覆盖 `--el-color-*` 变量。
