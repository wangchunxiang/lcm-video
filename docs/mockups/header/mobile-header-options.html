小屏顶栏 · 七个方案

硬性条件：logo 和站名都要显示；一级分类固定 5 项（首页 / 电影 / 剧集 / 综艺 / 动漫）且不会变多；二级分类不进顶栏。 375px 下容器 347px，品牌（logo 28 + 站名 110）占 146px、搜索 36px，导航只剩约 157px，而 5 个分类在 14px 下就需要 188px——所以单行方案（现状 / A / E）必然溢出。下面七个框都是 375px 宽、真实可交互，可拖滑块到 320 / 430 对比。

0现状基线

问题 1 品牌 + 5 个 16px 带图标的分类 + 搜索共约 348px，而可用宽只有 347px：375 下正好卡满、一个像素都不剩，320 下直接溢出，「动漫」被切掉；滚动条被隐藏，也没有「还能滑」的提示。
问题 2 导航项只有文字高度（约 20px），左右间隔 4px，热区远小于 44px。
问题 3 为了塞下，站名被隐藏（`SiteHeader.vue:100` 的 `hidden sm:inline`），品牌只剩一个 28px 图标。
问题 4 搜索一展开整条 header 消失（品牌 + 分类都没了）。

A渐隐 + 自动居中改动最小

改法 去掉图标，14px 纯文字、间隔 12px；右侧 34px 渐隐 + 小箭头提示可滑；点任意项后该项滑到中间；每项 `padding:15px 0` 把热区撑到 44px。
优点 只动 SiteHeader.vue 一个文件，不新增组件、不动 `--header-h`。
硬伤 站名 + logo 占掉约 146px，375 下导航只剩 ~157px，而 5 个分类要 188px（14px）/ 176px（12px）。保站名就做不了单行方案，A 只剩 31px 缺口，靠缩字距硬挤会牺牲触控。

B全部分类收进抽屉分类不限量

改法 顶栏只留 logo + 站名 + 当前分类（点击也是开抽屉）+ 搜索 + 菜单；5 个分类排成 2 列 44px 网格，选中项淡蓝底。点汉堡或分类名试试。
优点 顶栏极干净，分类数量随便加，触控全部达标。
缺点 分类从 0 次点击变 1 次；要新增 sheet 组件（滚动锁、遮罩、Esc），比 A 多约一个组件的量。

C底部 Tab 栏拇指可达

改法 顶部只剩 logo + 站名 + 搜索（56px 不变）；底部 56px tab 正好 5 个（首页 / 电影 / 剧集 / 综艺 / 动漫），不用「更多」；高度补 `env(safe-area-inset-bottom)`，页面内容补等量 `pb`。
优点 拇指最好点，顶部垂直空间全给内容，最像原生 App。
缺点 改动最大：播放页全屏、吸顶筛选条、页脚都要重新对；和现有「导航只在顶栏」的规范冲突；顶栏反而变空（只剩品牌 + 搜索）。

D拆两行（胶囊）不用点开

改法 第一行 logo + 站名 + 搜索，第二行 30px 胶囊横滑（选中淡蓝底），`scroll-snap` 吸附。
优点 站名保住，不需要额外点击，分类一直在页面上。
优点 5 个胶囊共约 292px ≤ 347px，375 下一屏全见、不用滑（320 正好卡满）。
缺点 顶栏从 56 → 约 92px；胶囊底色比纯文字重，和桌面那套纯文字导航不像同一个站。

D1两行 · 纯文字推荐

改法 第一行 logo + 站名 + 搜索（48px）；第二行就是桌面那条导航原样挪下来：16px 字 + `gap-8`(32px)，5 项共 288px。 375 可用 347px、320 可用 292px，都放得下，全程不用滑。
优点 logo + 站名都在，5 个分类全部第一眼可见，零点击；字号/间距和桌面完全一致，只是换了一行；改动只有 `SiteHeader.vue` 一个文件，`--header-h` 不用改。
代价 手机顶栏 56 → 约 88px，首屏少约 32px；比胶囊朴素一点（和桌面导航同一套观感）。

EA + B 组合推荐

改法 常见分类仍然零点击可见（A 的渐隐横滑 + 自动居中），末尾固定一个「全部」兜底 → 打开同一套抽屉。
优点 长尾分类有出口，顶栏高度不变，改动集中在 SiteHeader.vue + 一个新 sheet；不用碰 `--header-h` 和底部布局。
硬伤 同 A：单行放不下站名 + 5 个分类，差约 31px。
