# 数据库设计 v2（逐表结论）

> 本文只记录**已确认**的结论，讨论过程留在对话里。落库形式是「在现有 `lcm_video` 库里新建表」，不是对旧表做迁移。

## 0. 总则

| 项 | 约定 |
|---|---|
| 库 | 沿用现有 `lcm_video`（`.env` 的 `DB_NAME`），表建在同一实例 |
| 引擎 / 字符集 | InnoDB，`utf8mb4`（排序规则待定，见「未决事项」） |
| 表名 | 保留 `lcm_` 前缀，小写下划线；`lcm_collect_task_log` 这类「父_子」结构 |
| 列名 | 小写下划线 |
| 全局列 | 每张表都有 `id`、`created_at`、`updated_at`，不允许因为它们「没人读」而删除 |
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT`，业务键用唯一索引承载 |
| 枚举 | 一律 `TINYINT UNSIGNED` + 列注释，不使用字符串枚举 |
| 外键 | 暂不建物理外键（见「未决事项」） |
| 索引命名 | 唯一索引 `uk_*`，普通索引 `idx_*` |

## 2. `lcm_category` — 分类，固定两层

```sql
CREATE TABLE lcm_category (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  pid         BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '父分类 id，0 表示一级分类',
  name        VARCHAR(50)     NOT NULL DEFAULT '',
  alias       VARCHAR(50)     NOT NULL DEFAULT '' COMMENT 'URL 段，如 movie',
  match_names VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '源站分类名匹配串，逗号分隔，用于自动映射',
  sort        INT UNSIGNED    NOT NULL DEFAULT 0,
  is_show     TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1 前台显示 0 隐藏',
  created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_alias (alias),
  KEY idx_pid_sort (pid, sort)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

结论：整表保留。分类层级固定在两级（一级 `pid=0`，二级指向一级），不引入无限层级。

`match_names` 继续用逗号分隔的字符串，不拆成关联表——它只被自动映射按 `split(',')` 消费。

### 初始数据

建表后必须写入 34 行基础分类（4 个一级 + 30 个二级），数据取自现有 `lcm_video` 库的 `lcm_category` 表，见 `packages/db/seed/lcm_category.sql`。

| 一级分类 (id) | 二级分类数 | 二级分类 id 段 |
|---|---|---|
| 电影 (1) | 15 | 5–19 |
| 剧集 (2) | 5 | 20–24 |
| 综艺 (3) | 5 | 25–29 |
| 动漫 (4) | 5 | 30–34 |

`id` 必须显式指定：`pid` 依赖这些编号，且影片表的 `category_id` / `category_pid` 也指向它们。`created_at` / `updated_at` 交给列默认值。

## 3. `lcm_vod` — 影片主表

```sql
CREATE TABLE lcm_vod (
  id               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  category_id      BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '二级分类 id',
  category_pid     BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '一级分类 id，冗余字段，列表按一级分类筛选时避免 join',
  name             VARCHAR(255)    NOT NULL DEFAULT '',
  name_hash        CHAR(32)        NOT NULL DEFAULT '' COMMENT '规范化片名的 MD5，严格判重用',
  name_hash_loose  CHAR(32)        NOT NULL DEFAULT '' COMMENT '去掉标点后的 MD5，仅用于后台提示疑似重复',
  sub_name         VARCHAR(500)    NOT NULL DEFAULT '' COMMENT '别名',
  cover            VARCHAR(1000)   NOT NULL DEFAULT '',
  cover_host       VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '封面域名，写入 cover 时同步维护',
  actor            VARCHAR(1000)   NOT NULL DEFAULT '',
  director         VARCHAR(500)    NOT NULL DEFAULT '',
  writer           VARCHAR(500)    NOT NULL DEFAULT '',
  intro            VARCHAR(1000)   NOT NULL DEFAULT '' COMMENT '短简介，列表页用',
  content          TEXT            NULL                COMMENT '长简介，详情页用',
  remarks          VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '更新备注',
  release_date     VARCHAR(20)     NOT NULL DEFAULT '' COMMENT '上映日期，源站原文（Y-m-d / Y）',
  episode_count    INT UNSIGNED    NOT NULL DEFAULT 0,
  area             VARCHAR(100)    NOT NULL DEFAULT '',
  lang             VARCHAR(100)    NOT NULL DEFAULT '',
  year             INT UNSIGNED    NOT NULL DEFAULT 0,
  status           TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1 上架 0 下架',
  collected_at     DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '最后一次采集时间，列表排序用',
  created_at       DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_category_status (category_id, status),
  KEY idx_pid_status (category_pid, status),
  KEY idx_category_status_year (category_id, status, year),
  KEY idx_pid_status_year (category_pid, status, year),
  KEY idx_name_hash (name_hash),
  KEY idx_name_hash_loose (name_hash_loose),
  KEY idx_status_collected (status, collected_at),
  KEY idx_cover_host (cover_host),
  KEY idx_search (status, name, year, collected_at, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

改动与理由：

- **删 `letter` 与 `idx_letter`**：全仓没有任何读取方，只有采集写入和后台编辑表单写入。首字母检索没有对应界面。
- **`cover_host` 由生成列改为普通列**，`idx_cover_host` 保留：Prisma 不支持 MySQL 生成列，改普通列后由写入 `cover` 的同一处代码同步维护（采集写库、后台改封面、批量换/清封面三个入口）。
- **`release_date` 保留**，长度 255→20。
- **`intro` 与 `content` 不合并**：列表页只读 `intro`，详情页读 `content`；合并会让列表查询背上大字段。
- **`idx_search` 保留**：搜索用 `status = 1 AND name LIKE '%kw%'` 并只取 `id / year / collected_at / created_at`（`apps/server/src/routes/site/index.ts`）。前导通配符用不上索引做定位，但 `status` 能把范围收窄，且这四个列全在索引里，扫描不需要回表——删了会退化成全表扫。
- **`category_pid` 保留**：前台按一级分类筛选直接命中 `idx_pid_status`，不必回 `lcm_category` 找子分类。

## 4. `lcm_vod_play` — 播放线路数据

```sql
CREATE TABLE lcm_vod_play (
  id                 BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  vod_id             BIGINT UNSIGNED NOT NULL DEFAULT 0,
  source_id          BIGINT UNSIGNED NULL COMMENT 'NULL 表示手工添加的线路',
  source_from        VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '线路标识，如 lzm3u8',
  source_vod_id      VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '源站内的影片 id，用于增量比对',
  source_updated_at  DATETIME        NULL COMMENT '源站给出的更新时间，用于判断是否要更新',
  collected_at       DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  play_url           MEDIUMTEXT      NOT NULL COMMENT '整串播放地址：第1集$http://...#第2集$http://...',
  created_at         DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at         DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_vod_source_from (vod_id, source_id, source_from),
  KEY idx_source (source_id),
  KEY idx_source_vod_vod (source_id, source_vod_id, vod_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

改动与理由：

- **`source_id` 改可空**：手工添加的线路没有采集源。
- **不加 `play_line_id` 外键**：`lcm_play_line` 是「显示覆盖层」（改名、排序、停用），采集从不写它，前台用 `leftJoin` 按 `source_from` 关联，未注册的线路照样显示。加外键会让采集多一次 upsert，且线路注册后还要回填全量 `vod_play`。
- **`play_url` 不拆成「一集一行」**：十万影片 × 几十集会是数百万行，而解析只在请求单集播放时做一次。

⚠️ 注意：`source_id` 可空后，`uk_vod_source_from` 对 `NULL` 不去重（MySQL 唯一索引忽略 NULL）。手工添加的线路靠「同一 `vod_id` + `source_from`」在应用层保证唯一。

## 5. `lcm_collect_source` — 采集源站

```sql

  name              VARCHAR(50)     NOT NULL DEFAULT '',
  api_url           VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '采集接口地址',
  api_params        VARCHAR(500)    NOT NULL DEFAULT '' COMMENT '附加参数串，如 t=1',
  parse_url         VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '播放解析接口，空表示直连',
  is_enabled        TINYINT UNSIGNED NOT NULL DEFAULT 1,
  interval_sec      INT UNSIGNED    NOT NULL DEFAULT 3 COMMENT '请求间隔秒数，避免被封',
  pagesize          INT UNSIGNED    NOT NULL DEFAULT 100 COMMENT '每页条数 1~100',
  timeout           INT UNSIGNED    NOT NULL DEFAULT 30,
  retry_times       TINYINT UNSIGNED NOT NULL DEFAULT 2,
  last_sync_at      DATETIME        NULL,
  last_sync_status  TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0 未同步 1 成功 2 失败',
  last_sync_msg     VARCHAR(255)    NOT NULL DEFAULT '',
  play_from         VARCHAR(500)    NOT NULL DEFAULT '' COMMENT '最近一次采集到的线路标识，逗号分隔，后台候选提示用',
  created_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  KEY idx_enabled (is_enabled)

```

改动与理由：

- **删 `api_format`**：只支持 json 接口，xml 分支连同 `fast-xml-parser` 依赖一起移除。
- `last_sync_*` 三个字段保留：它同时记录「同步分类」这个动作的结果，并非只由采集运行写入。

## 7. `lcm_collect_source_category` — 源站分类映射

```sql
CREATE TABLE lcm_collect_source_category (
  id                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  source_id         BIGINT UNSIGNED NOT NULL DEFAULT 0,
  source_type_id    VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '源站分类 id（字符串）',
  source_type_name  VARCHAR(100)    NOT NULL DEFAULT '' COMMENT '源站分类名快照，同步分类时刷新',
  source_type_pid   VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '源站父分类 id，后台按两级树展示用',
  category_id       BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '映射到的本站分类，0 表示未映射',
  match_type        TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0 未匹配 1 自动匹配 2 手动指定',
  status            TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0 未映射 1 已映射 2 已忽略',
  created_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_source_type (source_id, source_type_id),
  KEY idx_category (category_id),
  KEY idx_source_status (source_id, status),
  CONSTRAINT ck_status_mapped CHECK ((status = 1) = (category_id > 0))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

结论：字段全保留。`status` 看似能由 `category_id` + 忽略标记推导，但「已忽略」是独立状态，删了必须补一个布尔列，属于等价替换且会丢掉按状态筛选的索引，因此不删。新增 CHECK 约束保证「已映射」与 `category_id > 0` 一致。

## 8. `lcm_collect_task` — 采集任务

```sql
CREATE TABLE lcm_collect_task (
  id               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  name             VARCHAR(50)        NOT NULL DEFAULT '',
  source_id        BIGINT UNSIGNED    NOT NULL DEFAULT 0,
  range_type       TINYINT UNSIGNED   NOT NULL DEFAULT 1 COMMENT '1 最近24小时 2 最近7天 3 最近30天 4 全部',
  cron             VARCHAR(50)        NOT NULL DEFAULT '' COMMENT '5 段 cron',
  is_enabled       TINYINT UNSIGNED   NOT NULL DEFAULT 1,
  last_run_at      DATETIME           NULL,
  last_run_status  TINYINT UNSIGNED   NOT NULL DEFAULT 0 COMMENT '0 未运行 1 运行中 2 成功 3 失败 4 已取消',
  last_run_msg     VARCHAR(255)       NOT NULL DEFAULT '',
  created_at       DATETIME           NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME           NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_source (source_id),
  KEY idx_enabled (is_enabled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

改动：

- **`last_run_status` 取值重排**为 `0 未运行 / 1 运行中 / 2 成功 / 3 失败 / 4 已取消`：进行中状态在前、终态在后。
- **开始运行时写入 1（运行中）**；结束时写终态；服务启动时的清收逻辑必须把残留的 `1` 改写成 `3`（失败，附「服务重启，采集中断」）。
- 前端提示文案同步改为「最近 24 小时 / 最近 7 天 / 最近 30 天 / 全部」，与固定小时数一致。

## 9. `lcm_collect_task_log` — 采集记录（原 `lcm_collect_log`）

```sql
CREATE TABLE lcm_collect_task_log (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  task_id         BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0 表示手动采集',
  source_id       BIGINT UNSIGNED NOT NULL DEFAULT 0,
  task_name       VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '任务名快照，任务删除后仍可显示',
  range_type      TINYINT UNSIGNED NOT NULL DEFAULT 1,
  status          TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1 运行中 2 成功 3 失败 4 已取消',
  total_pages     INT UNSIGNED    NOT NULL DEFAULT 0,
  last_page       INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '已完成到第几页，断点续采锚点',
  resume_count    INT UNSIGNED    NOT NULL DEFAULT 0,
  interrupted_ms  BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '累计中断毫秒，用于扣减停机时间',
  total           INT UNSIGNED    NOT NULL DEFAULT 0,
  inserted        INT UNSIGNED    NOT NULL DEFAULT 0,
  updated         INT UNSIGNED    NOT NULL DEFAULT 0,
  skipped         INT UNSIGNED    NOT NULL DEFAULT 0,
  ignored         INT UNSIGNED    NOT NULL DEFAULT 0,
  failed          INT UNSIGNED    NOT NULL DEFAULT 0,
  message         VARCHAR(500)    NOT NULL DEFAULT '',
  started_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  finished_at     DATETIME        NULL,
  created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_task_started (task_id, started_at),
  KEY idx_started (started_at),
  KEY idx_source_started (source_id, started_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

改动与理由：

- **改名**：这张表是 `lcm_collect_task` 的执行记录，命名与 `lcm_collect_source` / `lcm_collect_source_category` 的父子结构保持一致。
- **新增 `task_name` 快照**：删除任务只删任务本身、记录保留（`apps/server/src/routes/admin/tasks.ts`），没有快照就只剩一个悬空 id。手动采集时写 `手动采集·<源站名>`。
- **`status` 与任务表同一套取值**（1 运行中 / 2 成功 / 3 失败 / 4 已取消），前端可共用一份映射。
- **新增 `idx_source_started`**：记录页支持按源站筛选，原来只有按任务、按时间的索引。
- `source_name` **不做**快照：删除源站时该源的记录会一并删除，不存在显示空名的情况。
- 6 个计数器不合并：`total = inserted + updated + skipped + ignored + failed` 是记录详情的对账关系。

## 10. `lcm_collect_task_log_detail` — 采集记录明细（原 `lcm_collect_log_detail`）

```sql
CREATE TABLE lcm_collect_task_log_detail (

  log_id      BIGINT UNSIGNED NOT NULL DEFAULT 0,

  inserted    INT UNSIGNED    NOT NULL DEFAULT 0,
  updated     INT UNSIGNED    NOT NULL DEFAULT 0,
  skipped     INT UNSIGNED    NOT NULL DEFAULT 0,
  ignored     INT UNSIGNED    NOT NULL DEFAULT 0,

```

结论：字段不变，仅随主表改名。`fail_detail` 用 JSON 不拆表——只在详情页原样展示，不参与查询。`(log_id, page)` 不建唯一索引：续采重跑同一页会再插一行，历史留痕优先。

## 12. `lcm_ad_feature` — 广告特征库

```sql
CREATE TABLE lcm_ad_feature (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  source_id   BIGINT UNSIGNED NOT NULL DEFAULT 0,
  kind        TINYINT UNSIGNED NOT NULL DEFAULT 2 COMMENT '1 片头 2 片中 3 片尾',
  durations   VARCHAR(255)    NOT NULL COMMENT '分片时长指纹，逗号分隔',
  total_ms    INT UNSIGNED    NOT NULL DEFAULT 0,
  hit_vods    INT UNSIGNED    NOT NULL DEFAULT 0,
  sample      JSON            NULL COMMENT '[{vod_id,vod_name,start,start_sec,url}]',
  created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_source_durations (source_id, durations),
  KEY idx_source (source_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

结论：不变。`durations` 用字符串而非 JSON，是为了让唯一索引成立。

## 13. `lcm_vod_merge_ignore` — 重复影片忽略名单

```sql
CREATE TABLE lcm_vod_merge_ignore (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  merge_key  VARCHAR(64)     NOT NULL COMMENT 'uk_merge_key：auto:<hash> 或 suspect:<hash>~<year>',
  kind       TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1 严格重复 2 疑似重复',
  created_at DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_merge_key (merge_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

改动与理由：

- **补齐 `id`、`updated_at`**：原来用 `merge_key` 当主键且没有 `updated_at`，与全局规则冲突。
- **`kind` 从 `VARCHAR(10)`（`auto`/`suspect`）改为 `TINYINT`**（1/2）：字符串枚举写错一个字母不报错、只会静默失效。
- 该表原来不在 Drizzle schema 里，只能裸 SQL 访问；新库中作为正式 model 存在。

## 14. `lcm_source_rule` — 采集源地址替换规则

```sql
CREATE TABLE lcm_source_rule (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  source_id  BIGINT UNSIGNED NOT NULL DEFAULT 0,
  kind       TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1 播放地址 2 图片地址',
  from_url   VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '源地址前缀',
  to_url     VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '替换成的前缀，空表示删除该前缀',
  is_enabled TINYINT UNSIGNED NOT NULL DEFAULT 1,

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 15. `lcm_cover_check` — 图片域名体检

```sql
CREATE TABLE lcm_cover_check (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  host        VARCHAR(255)    NOT NULL DEFAULT '' COMMENT '封面域名，不含协议与路径',
  vod_count   INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '检查时引用该域名的影片数快照',
  status      TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '0 未检查 1 正常 2 失效 3 无法验证',
  sample_ok   INT UNSIGNED    NOT NULL DEFAULT 0,
  sample_fail INT UNSIGNED    NOT NULL DEFAULT 0,
  message     VARCHAR(255)    NOT NULL DEFAULT '',
  checked_at  DATETIME        NULL,
  created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_host (host),
  KEY idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

结论：保留域名级设计，每个域名抽查 2 张，字段不变；`host` 由 100 扩到 255（DNS 名字上限 253）。

`status = 3`（无法验证）与 `2`（失效）必须区分：前者是我们这台服务器访问不到，不一定是图挂了。

## 16. `lcm_setting` — 站点配置（KV）

```sql
CREATE TABLE lcm_setting (
  `name`     VARCHAR(50) NOT NULL DEFAULT '' COMMENT '配置键',
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `value`    TEXT        NULL,
  created_at DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_name (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

结论：保留 KV 结构，5 列不变。原因：后台设置页是**元数据驱动**的（前端按 `SETTINGS` 数组渲染表单，后端按同一份元数据校验），改成单行宽表就要维护「列 ↔ 元数据」两套映射，且每加一个开关都要迁移。

类型安全改由代码保证：在 `packages/shared` 用一个 zod object 描述全部配置键的类型与默认值，读取统一走 `SettingService.get()`。缓存也收敛到这里（保存后立即失效）。

配置键共 18 个，其中 `site_theme` **删除**（不再支持多主题），其余保持。
