## 0. 页面数量与路由的实际情况

盘点中发现一处与任务描述不一致的数字，先说明：

- `apps/admin/src/menu.ts` 的 `flatMenus()` 展开后是 **16 个叶子路径**：`/dashboard` + 采集管理 6 + 内容管理 2 + 播放管理 2 + 高级工具 3 + 系统管理 2。
- `apps/admin/src/router/index.ts` 的 `implemented` 映射表里是 **15 项**（不含 `/dashboard`），`/dashboard` 在 `/` 的 `children` 中单独注册了一条静态路由。
- 因此实际已实现页面是 **16 个**（15 + 数据概览）。任务描述写的「15 个已实现页面」应指 `implemented` 映射表的 15 项，菜单叶子实际为 16 项。
- `placeholderRoutes` 由 `flatMenus()` 过滤掉 `/dashboard` 与已实现项生成，当前过滤后为空集，所以 `views/Placeholder.vue`（13 行）**实际不会被任何路由使用**，只是被静态 import。
- 全部页面组件在 router 中**静态 import**，没有路由级懒加载。

主要通用风险（按影响排序）：

1. **表格列模型**：123 个 `el-table-column` 中大量使用 `#default="{ row }"` 插槽、`show-overflow-tooltip`、`fixed`、`min-width`、`#empty`。antd `Table` 需要改写成 `columns[].render` + `scroll.x`，属于纯体力活但量最大，估占迁移总工时的 30% 左右。
2. **树形表格**：Mappings（手动建树 + `tree-props`）与 Categories（两级树）需要改成 antd `treeData` + `expandable`，行内树选择要从 `el-tree-select` 换成 `TreeSelect`，并自行保证 `check-strictly` 语义。
3. **命令式服务**：243 行 `ElMessage/ElMessageBox/ElNotification/ElLoading` 需要替换；其中 `ElMessageBox` 的「两段式确认」「确认按钮文案定制」「`error !== 'cancel'` 判定」在 antd 中行为不同（reject 值/异常类型），是最容易引入回归的地方。
4. **指令与 DOM 操作**：`v-loading`（16 文件）→ `Spin` 包裹；`ResizeObserver` 表高（10 文件）→ 需重写一套 `useTableHeight`，antd `Table` 的 `scroll.y` 行为与 EP 不同（表头/表体分离方式不同）。
5. **样式体系**：1,767 行样式中大量 `--el-*` 变量与 `:deep()`；antd 用 CSS-in-JS token，覆盖方式完全不同，自绘页面（Config/Merge/Logs）需重画。
6. **表单校验缺失**：63 个 `el-form-item`、**0 条 `:rules`**，全部手写 `if + ElMessage.warning`；迁移到 antd `Form` 时校验时机/错误展示会变化，建议迁移时改为 schema 校验（见 3.5）。
7. **轮询与计时器生命周期**：Tasks/Logs 依赖 `onUnmounted` 清理；React 下需 `useEffect` cleanup，易漏。
8. **半成品状态**：`/playback/config` 的去广告链路源码自述为演示流程，迁移前需先与后端确认接口是否可用，否则会白做。
9. **拖拽排序**：Lines 用原生 HTML5 draggable（无第三方库），React 下需引入 dnd-kit 或重写。
10. **无路由懒加载 / 全量图标注册**：迁移时若照搬，首屏体积问题会延续；建议迁移时一起改成按需。

### 3.5 保留 Vue 的「轻重构」5 条建议

1. **统一请求层与类型化 DTO**
   把 `api.get<T>` 的 DTO 从各 SFC 抽到 `packages/shared`（现在 15 个页面的接口返回类型全部内联声明）；请求层统一处理错误提示（现在每个页面 30+ 处 `try/catch + ElMessage.error` 重复），并统一用 `query` 对象传参——顺手修掉 `SourceRules.vue` 里 `api.get('/source-rules', { params })` 的传参写法（会导致筛选条件失效）。

2. **抽公共表格组件 `DataTable`**
   把「固定表头高度自适应（ResizeObserver）+ 分页 + 空态 + 批量选择 + loading」收敛成一个组件，替掉 10 份重复的表高代码和 7 份重复的分页模板；`el-table-column` 的 123 处列定义保留在页面侧，但壳子统一。

3. **表单校验 schema 化**
   引入 zod（或 EP 的 `:rules`）建立每页 schema，替换 Sources 的 `readNumber()`、Account 的密码一致性、Site 的数字字段等手写校验；`MergeRules`/`Config`/`Site` 三处「本地常量数组 + 渲染分支」可合并为一个 `FieldRenderer`（text/image/select/textarea/switch/radio 六种 kind）。

4. **抽组合式函数去重**
   `usePagedList`（分页 + 筛选 + loading + 空页回退）、`usePolling`（5s 轮询 + 页面隐藏暂停 + 卸载清理）、`useDangerConfirm`（两段式危险确认 + 文案模板）三个 composable，可直接消掉 Tasks/Logs 的计时器样板与 18 处 `ElMessageBox.confirm` 的重复文案。

5. **路由与依赖按需化**
   路由改为 `() => import(...)` 懒加载；EP 改为按需引入、图标按需注册（现在 `main.ts` 全量注册所有图标，且菜单 `icon` 字段根本没被渲染）；同时把 `Placeholder.vue` 这类实际不可达的代码清掉。

## 5. 一页纸结论

- **规模**：16 个路由页面 + 7 个公共 SFC，共 8,502 行 Vue；script 占 50.9%，template 26.3%，style 20.8%。
- **复杂度分布**：复杂 8（Sources / Mappings / Tasks / Logs / Vods(+Dialog) / Config / Merge / CoverCheck）、中等 5（SourceRules / MergeRules / Categories / Lines / Data）、简单 4（Dashboard / Site / Account / Login）。
- **最复杂三页**：`/playback/config`（流式分析 + hls + 3 表 2 弹窗，且有演示态）、`/tools/merge`（自绘双栏工作台 + 两段式批量）、`/collect/logs`（双计时器 + 抽屉二级分页 + 续采边界）。
- **组件集中度**：`el-table-column`(123) + `el-button`(122) + `el-form-item`(63) 三者占全部组件用量的近一半，表格/表单是迁移主战场。
- **迁移成本**：React + antd 约 **60–72 人日**（中位 65），其中表格列改写与确认流替换是两大风险。
- **不迁移的话**：最值得先做的是请求层 + 公共表格 + schema 校验 + 三个 composable + 路由懒加载，预计能把 10 份表高样板、18 处确认文案、30+ 处错误提示收敛掉。
