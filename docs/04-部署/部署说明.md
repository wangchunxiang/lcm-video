# 部署说明

## 镜像来源

**方式一：GitHub Actions → Docker Hub**

push 到 Gitee 后由仓库镜像同步到 GitHub，Actions 自动构建 `linux/amd64` 镜像并推送 Docker Hub，工作流见 `.github/workflows/docker.yml`。GitHub 仓库需要配置两个 Secret：

- `DOCKERHUB_USERNAME`
- `DOCKERHUB_TOKEN`（Read & Write）

NAS 的 `.env` 里指定镜像：

```dotenv
APP_IMAGE=docker.io/<用户名>/lcm-video:latest
```

更新：

```bash
docker compose pull app
docker compose up -d app
```

公开镜像不需要 `docker login`。NAS 访问 Docker Hub 不稳定时，可以把工作流改成推阿里云 ACR，替换登录地址和 tag 即可。

**方式二：本地构建后导入**

```bash
npm run docker:export     # docker build + docker save -o lcm-video.tar
```

ARM 机器给 x86 NAS 构建时指定平台：

```bash
docker build --platform linux/amd64 -t lcm-video:latest .
docker save lcm-video:latest -o lcm-video.tar
```

## NAS（fnOS）部署

1. 「Docker → 镜像 → 导入」选择 `lcm-video.tar`
2. 新建部署目录（例 `/vol1/1000/Docker/lcm-video`），放入仓库的 `docker-compose.yml`，把 `.env.example` 复制为 `.env`，填好 `JWT_SECRET` 与 `DATABASE_URL`
3. 「Docker → Compose → 新建项目」选择该目录，或 SSH 执行 `docker compose up -d`
4. 打开 `http://NAS局域网IP:3100/`，后台在 `/admin/`

`DATABASE_URL` 的主机名按数据库部署方式选择：

| 数据库位置 | 写法 |
| --- | --- |
| 容器已映射 3306 | `mysql://用户:密码@NAS局域网IP:3306/lcm_video` |
| 容器未映射端口 | 加入它的 Docker 网络，主机名用容器名，如 `@mariadb:3306` |
| 装在 NAS 宿主机 | `@host.docker.internal:3306` |

容器启动时自动执行迁移；数据在外部数据库里，重建容器不会丢数据。

## 空库首次初始化

空库第一次启动时，迁移之后会自动补齐：

- `lcm_category` 为空 → 导入初始分类
- `lcm_setting` 为空 → 导入站点配置默认值
- `lcm_admin_user` 为空且配置了 `ADMIN_PASSWORD` → 创建管理员

```dotenv
ADMIN_USERNAME=admin          # 可选，默认 admin
ADMIN_PASSWORD=改成至少6位的密码
ADMIN_NICKNAME=管理员          # 可选
```

只对空表生效；不想自动导入分类/配置时设 `SEED_ON_START=false`。登录后建议把 `ADMIN_PASSWORD` 从 `.env` 删掉，账号已经落库。

## 注意事项

- **只跑单副本**：验证码、登录失败计数、定时采集都在进程内存里，多副本会导致验证码失效、锁定绕过、任务重复
- **数据库时区必须是 `+08:00`**，两处一起给：容器环境变量 `TZ: Asia/Shanghai`（让 `@@system_time_zone` 变 `CST`）+ mysqld 启动参数 `--default-time-zone=+08:00`（让 `@@global.time_zone` 直接是 `+08:00`）。改完 `docker compose up -d --force-recreate <服务>`（普通 `restart` 不会重新注入环境变量），然后**重启应用**（会话时区只在建连时读一次）。自查：`SELECT @@global.time_zone, @@system_time_zone, NOW();` 三个都要是北京时间，否则 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE` 会写 UTC，和应用显式写入的时间差 8 小时。
- 数据库和 `.env` 都不进镜像

## 测试

`npm run test:e2e` 在真实 MySQL 上跑完整 HTTP 链路，装配方式复刻 `apps/server/src/main.ts`：

- 测试库由 `TEST_DATABASE_URL` 指定；不配则把 `DATABASE_URL` 的库名加 `_test` 后缀，库名不以 `_test` 结尾会拒绝运行
- 每次运行会清空测试库的表并由迁移重建
- 串行执行（`fileParallelism: false`），一次约 10 秒
