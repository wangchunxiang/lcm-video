# 前端决策清单（v3 后台 + Web 前台）

记录时间：2026-11-11。用途：供审查本轮「后台前端收尾 + Web 前台实现」过程中做出的判断。
范围：`apps/admin`（Vue3 + Element Plus）与 `apps/web`（Vue3，自写样式），以及为前台补的两个只读接口。
约束：后台页面此前已按 v3 契约（`/api/admin/*`、nest-crud 查询协议、Bearer token）实现；本轮不改后台数据层，只补前台与必要的后端只读字段。

## 1. 总体决策

| # | 决策 | 备选 | 理由 | 影响/风险 |
|---|------|------|------|-----------|
| D1 | 后台继续用 Element Plus；前台用 **Tailwind CSS 4 + 自写组件**（样式走 tokens，组件在 `apps/web/src/components`），不引视觉组件库 | 两端共用 Element Plus；或前台引 Vant/Naive 等视觉组件库 | 前台是公开站，只有展示/筛选/播放交互，EP 的体积与主题覆盖成本不划算；Vant 是移动优先、桌面端会怪；自写组件只管本站需要的形态，样式改动不会外溢 | 交互细节（焦点、a11y）要自己兜；没有现成的复杂组件可用 |
| D2 | 前台采用**暗色影院风**（沿用 v2 主题取值）：`--bg:#0a0c0f`、卡片 `#171a20`、主色 `#3b82f6`、播放器区域黑底 | 亮色主题（`#2563eb`） | 与 v2 前台观感一致，海报在深底上更突出；改版时用户明确要求「先仿照 v2」 | 若要回亮色，只需替换 `tokens.css` 的颜色变量，并重新校对阴影与筛选 chip 对比度 |
| D3 | 不引入 Pinia，用 `src/site.ts` 的 `reactive` 单例承载站点配置与分类树 | Pinia / provide-inject | 全局状态只有「配置 + 分类 + ready」，一个模块足够 | 后续若出现用户态再评估 |
| D4 | 页面级 SEO 用 `useSeo()` 组合式写 `document.title` 与 meta | 路由 meta 静态标题 | 详情/播放/搜索标题依赖接口数据，必须运行时写 | 无 SSR，社交爬虫拿不到动态 meta（与「纯 SPA」决策一致） |
| D5 | 后台不新增「数据处理」页（v2 `/tools/data`） | 复刻 v2 的四个危险操作 | v3 后端没有 `/api/admin/tools/*`；URL 替换已由「采集规则 + apply」覆盖，封面修复由「封面检测」覆盖，删源线路/清理无线路影片无对应接口 | 若确需清理能力，应先定后端接口再补页面 |

## 2. 路由与 URL

| # | 决策 | 理由 |
|---|------|------|
| D6 | 前台路由：`/`、`/list/:alias`、`/detail/:id`、`/play/:id/:lineId?/:ep?`、`/search`、`/:pathMatch(.*)*` | 与技术方案 §7.3 对齐；`/list` 重定向到 `/list/all`；未知路径进 404 而不是空白页 |
| D7 | 播放页第二段用 **`lcm_vod_play.id`**（lineId），不是线路序号 | 线路排序会变（后台可拖排序/停用），序号会漂移导致分享链接串台；id 稳定 |
| D8 | 前端把 lineId 换算成接口的 **0 基 `line` 下标** 再请求 `/api/web/play` | 后端契约（v2 沿用）以 `line` 为下标，未改后端语义，避免影响其它调用方 |
| D9 | 进入播放页后把 URL 规范化为 `/play/{id}/{lineId}/{ep}`（`router.replace`） | 保证刷新/复制链接可复现；越界集数回落到最后一集 |
| D10 | 换集、换线路用 `push`；仅规范化用 `replace` | 换集/换线路是用户可感知的导航，需要后退；规范化不应产生历史记录 |
| D11 | 列表页所有筛选（type/year/sort/page）都放 query，path 只留 alias | 与技术方案「路径定页面、query 定筛选」一致，可分享、可后退 |

## 4. 播放器

| # | 决策 | 理由 | 风险 |
|---|------|------|------|
| D16 | 直链播放用 **ArtPlayer**（`artplayer@^5.4.0`），m3u8 通过 `customType.m3u8` 交给 hls.js | 用户决定（2026-11-12）与技术方案 §6.4 一致；控制条、设置面板（倍速/比例/网页全屏）、快捷键由播放器提供，站点配置里的播放器开关都能落到 ArtPlayer 选项上 | 播放页 chunk 增到约 744KB（gzip 226KB）；ArtPlayer 与 hls.js 需一起升级 |
| D17 | `customType.m3u8` 内部仍按能力探测：`canPlayType('application/vnd.apple.mpegurl')` 原生优先，否则 hls.js；hls 致命错误销毁后回退原生再试 | iOS/Safari 原生 HLS 更省电、少一层 MSE；桌面 Chrome 走 hls.js | 两套内核行为有差异（如字幕/清晰度），目前片源没有多清晰度 |
| D18 | hls 配置 `{ enableWorker: true, lowLatencyMode: false, maxAudioFramesDrift: 5 }` | 与文档一致；点播不需要低延迟 | — |
| D19 | `parse_url` 含 `{url}` 时替换为 `encodeURIComponent(播放地址)`，否则直接拼接 | 兼容「模板型」与「前缀型」解析接口（文档 §6.1） | 个别源要求不编码，需按源微调时改这里 |
| D20 | 续播用 `localStorage` 键 `lcm:resume:{vodId}:{lineId}:{ep}`，每 5s 记录、播完清除、换集前强制写一次 | 无登录态，只能本地存；键里带集数，避免「第 1 集看到 30 分、切到第 2 集又跳到 30 分」 | 换设备不同步（游客站可接受） |
| D21 | 自动连播仅当 `player_autonext=1`，自动播放仅当 `player_autoplay=1` | 尊重后台开关；浏览器自动播放策略下仍可能被拦截，失败不报错 | 用户可能需再点一次播放 |
| D22 | 播放失败统一文案「该线路暂不支持在线播放」，并允许切线路 | 与文档 §6.4 文案一致 | — |

## 5. 页面交互

| # | 决策 | 理由 |
|---|------|------|
| D23 | 首页三个区块的「更多」按后端 row.title 映射到 `/list/all?sort=time` / `?sort=new`，未知标题回落 `/list/all` | 后端 `more` 仍是 v2 路径（`/today`、`/category/all`），v3 没有这些路由；前端做映射避免改后端 |
| D24 | 列表页每页条数取站点 `listPageSize`（默认 24），分页组件只发 `page`，由页面换算 `skip` | 与后端 `take/skip` 契约一致，且换页大小只需改设置 |
| D25 | 详情页线路切换只改页面状态，不写 URL（地址始终 `/detail/:id`），剧集点击进入播放页 | 线路只是「看哪条线路的剧集」，刷新回第一条可接受；地址栏保持干净，点 tab 不产生导航 |
| D26 | 搜索页 `wd` 为空不发请求，直接展示空态；`noindex` | 后端对空 wd 返回空集，前端不必打接口；搜索页不应被收录 |
| D27 | 封面破图统一回落 `/img/poster-placeholder.svg`；无封面不显示灰块 | 采集源封面缺失很常见 |
| D28 | 剧集一次全渲染（不做分页/虚拟滚动） | 单部影片集数通常 < 200，DOM 压力可接受；原型也是全量 |
| D29 | 页头只显示前 8 个一级分类，其余通过「全部影片」进入列表页筛选 | 分类可达 10+，全放会挤爆导航；与 v2 视觉一致 |

## 6. 明确不做

- 排行、专题、评论、资讯（技术方案 §1.2 已排除）。
- 前台登录/收藏/历史（纯游客站）。
- 统计代码不执行：`site_stats_code` 只随配置返回，不 `innerHTML` 注入（XSS 风险）；如确需统计，应改为后台白名单脚本或独立域。
- 后台「数据处理」页（见 D5）。
- Web 端不做 SSR/预渲染（与技术方案 §4 的 SPA 决策一致）。

## 9. 响应式与组件体系（2026-11-13）

背景：用户明确「主要考虑 PC 端和移动端的响应式，SEO 不考虑」，因此不引入 SSR/Next/Nuxt，改为在 Vue SPA 内做「一套页面 + 双端形态」。

第一版曾引入 shadcn-vue（`reka-ui` 无样式原语 + `cva`），用户看过列表页后判定「太素、像另一个站」，于是**改为 Tailwind 4 负责布局、组件全部自写**：视觉以 `tokens.css` 的变量为准，按原 `site.css` 的设计规格（卡片阴影、2/3 海报、胶囊按钮与 chips、渐变 hero）手写，不依赖任何组件库。

| # | 决策 | 备选 | 理由 | 风险 |
|---|------|------|------|------|
| D30 | **一套页面**，不做 `/m/*` 移动端独立站；两端差异只落在组件层 | 两套页面/两套路由 | 站点两端都是「列表 → 详情 → 播放」，差异只在排布；两套页面会让筛选/分页/播放状态逻辑重复，链接也不通用 | 手机端交互形态特殊的组件（抽屉、横滑剧集）需要单独写 |
| D31 | 前台用 **Tailwind CSS 4 + 自写组件**（`components/ui/` 只剩 `Sheet`、`Skeleton`；图标直接用 `lucide-vue-next` 组件，不套封装层） | shadcn-vue / 视觉组件库 / 纯手写 CSS / 自建图标组件 | 组件库的默认皮肤与站点风格差距大，改皮肤的成本高于自己写；自写组件样式全是 Tailwind class，改一处不影响别处。图标不自己画也不封装：lucide 可 tree-shake，加包装层反而要维护一份名字映射 | 图标尺寸、`shrink-0` 要写到每个使用点；描边只能用 lucide 默认的 2 |
| D32 | 断点：**sm 640 / md 768 / lg 1024 / min-[1400px]**，栅格 2/3/4/6/8 列 | 原来的 6 档（1400/1180/1100/900/640/420） | 4 档足够区分手机/平板/桌面/大屏，且与 Tailwind 默认前缀一致 | 1400~1600 之间列数跳变需要抽查 |
| D33 | Tailwind 只引 `theme` + `utilities` 两层，**不引 preflight**，另写 `base.css` 做最小重置 | 引完整 Tailwind（含 preflight） | preflight 会重置标题/列表/表单默认样式，与站点既有排版冲突；最小重置只做 box-sizing、margin、媒体元素、表单元素 | 新组件必须显式写边框/间距，不能依赖浏览器默认 |
| D34 | 手机端列表用 **「加载更多」**，桌面端保留分页器 | 两端都用分页 / 两端都用无限滚动 | 手机上点分页器体验差；加载更多保留 URL `page`，可后退、可分享 | 手机端刷新第 2 页时只会加载当前页（不自动补齐前面页） |
| D35 | 筛选区两端同构：**行式 chips（类型/年份/排序）**，手机上自然换行 | 手机端用底部抽屉 | v2 就是行式 chips，一屏内能直接看到当前筛选；抽屉要多一次点击，且看不到已选项 | 375px 下年份 chips 会占 4~5 行，首屏内容被压低 |
| D36 | `useBreakpoint()` 只用于**换组件形态**，纯视觉差异一律用 Tailwind 前缀 | 用 JS 判断宽度控制样式 | JS 判断会丢失首帧一致性，也容易两端逻辑分叉 | 模板里出现 `isMobile && class` 视为坏味道 |
| D37 | **删除 `site.css`**，所有页面改用 Tailwind | 新旧样式并存 | 两套样式并存必然漂移；页面迁移完成后一次性删除 | 旧类名（`.vod-grid` 等）不再存在，新增页面必须用 Tailwind |

## 10. 播放页（2026-11-16）

参考 v2 主题的布局（`git show v2:themes/default/play.liquid`：左播放器 + 右侧播放控制台，移动端是「上一集 / 选集 / 下一集 + 底部抽屉」），只借结构，样式全部按当前令牌重写。

| # | 决策 | 备选 | 理由 | 风险 |
|---|------|------|------|------|
| D38 | 布局：**上下结构**——播放器（16:9 占满容器）→ 标题行（片名 20px + 当前集小字，右端一组：上一集 / 下一集 / 自动连播开关，按钮无边框 `h-8 px-2`）→ 线路 tab（与详情页同一套下划线样式）+ 剧集网格（与详情页同一套格子样式，一整条内部滚动） | 左右分栏（播放器 + 右侧 360px 选集栏） | 播放器拿到全宽；手机与桌面同一套结构，不用为窄屏换形态 | 1440×900 下选集在首屏之外，要往下滚一点 |
| D39 | **换集就地切换**：只改 `current`，`PlayerBox` 用 `art.switchUrl()` 换源，不再请求 `/api/web/play`，也不销毁 ArtPlayer | 每次 `router.push` 重新请求 + 重建播放器（原实现） | 换集不再黑一下、不再多一次接口；前进/后退也走同一条路径 | 依赖 `art.switchUrl` 的行为（会重跑 `customType`），升级 ArtPlayer 要回归换集 |
| D40 | 换线路仍要**取一次新线路的集数列表**（接口按线路返回剧集），取回后同样就地换源，并保持当前集数（新线路集数不够才回落） | 预取全部线路的剧集 | 单部影片最多几百集，全线路预取会明显放大首屏响应；换线路是低频操作 | 换线路有一次接口往返，弱网下会顿一下 |
