# 前端决策清单（v3 后台 + Web 前台）

记录时间：2026-11-11。用途：供审查本轮「后台前端收尾 + Web 前台实现」过程中做出的判断。
范围：`apps/admin`（Vue3 + Element Plus）与 `apps/web`（Vue3，自写样式），以及为前台补的两个只读接口。
约束：后台页面此前已按 v3 契约（`/api/admin/*`、nest-crud 查询协议、Bearer token）实现；本轮不改后台数据层，只补前台与必要的后端只读字段。

## 1. 总体决策

| # | 决策 | 备选 | 理由 | 影响/风险 |
|---|------|------|------|-----------|
| D1 | 后台继续用 Element Plus；前台不引 UI 库，自写组件 + 全局 CSS | 两端共用 Element Plus；或共用自研组件库 | 前台是公开站，只有展示/筛选/播放交互，EP 的体积与主题覆盖成本不划算；后台表格/表单密集，EP 效率最高 | 两套组件风格需分别维护，但互不影响 |
| D2 | 前台采用亮色主题，主色 `#2563eb`，播放器区域黑底 | 暗色影院风（原型 play-layouts 的 `#0A0C0F`） | 与 v2 PWA `theme_color` 一致，长列表阅读更稳；原型暗色只是布局稿 | 若审查倾向暗色，只需替换 `tokens.css` 的颜色变量 |
| D3 | 不引入 Pinia，用 `src/site.ts` 的 `reactive` 单例承载站点配置与分类树 | Pinia / provide-inject | 全局状态只有「配置 + 分类 + ready」，一个模块足够 | 后续若出现用户态再评估 |
| D4 | 页面级 SEO 用 `useSeo()` 组合式写 `document.title` 与 meta | 路由 meta 静态标题 | 详情/播放/搜索标题依赖接口数据，必须运行时写 | 无 SSR，社交爬虫拿不到动态 meta（与「纯 SPA」决策一致） |
| D5 | 后台不新增「数据处理」页（v2 `/tools/data`） | 复刻 v2 的四个危险操作 | v3 后端没有 `/api/admin/tools/*`；URL 替换已由「采集规则 + apply」覆盖，封面修复由「封面检测」覆盖，删源线路/清理无线路影片无对应接口 | 若确需清理能力，应先定后端接口再补页面 |

## 2. 路由与 URL

| # | 决策 | 理由 |
|---|------|------|
| D6 | 前台路由：`/`、`/list/:alias`、`/detail/:id`、`/play/:id/:lineId?/:ep?`、`/search`、`/:pathMatch(.*)*` | 与技术方案 §7.3 对齐；`/list` 重定向到 `/list/all`；未知路径进 404 而不是空白页 |
| D7 | 播放页第二段用 **`lcm_vod_play.id`**（lineId），不是线路序号 | 线路排序会变（后台可拖排序/停用），序号会漂移导致分享链接串台；id 稳定 |
| D8 | 前端把 lineId 换算成接口的 **0 基 `line` 下标** 再请求 `/api/site/play` | 后端契约（v2 沿用）以 `line` 为下标，未改后端语义，避免影响其它调用方 |
| D9 | 进入播放页后把 URL 规范化为 `/play/{id}/{lineId}/{ep}`（`router.replace`） | 保证刷新/复制链接可复现；越界集数回落到最后一集 |
| D10 | 换集、换线路用 `push`；仅规范化用 `replace` | 换集/换线路是用户可感知的导航，需要后退；规范化不应产生历史记录 |
| D11 | 列表页所有筛选（type/year/sort/page）都放 query，path 只留 alias | 与技术方案「路径定页面、query 定筛选」一致，可分享、可后退 |

## 3. 数据层与后端契约改动

| # | 决策 | 说明 |
|---|------|------|
| D12 | `PlayLine` 增加 `id` 与 `parseUrl` 两个字段 | 前台需要稳定线路 id（D7）与解析地址（决定 iframe/直链） |
| D13 | 新增公开只读 `GET /api/site/config`，返回站点信息 + 播放器开关 | 前台页头/页脚/播放器行为都依赖配置；复用后台 `setting` 表，不新增表 |
| D14 | 配置读取复用 `SettingService`，`list_page_size` 夹在 12–60 | 防止后台填 0/超大值把列表打爆；越界回退 24 |
| D15 | 接口客户端仍放 `apps/web/src/api/portal.ts`，类型与后端 service 返回逐字段对应 | `@lcm/shared` 目前放的是跨端纯函数/枚举，把 HTTP DTO 挪过去收益低；已在文件头留 TODO |

## 4. 播放器

| # | 决策 | 理由 | 风险 |
|---|------|------|------|
| D16 | 直链播放用 **ArtPlayer**（`artplayer@^5.4.0`），m3u8 通过 `customType.m3u8` 交给 hls.js | 用户决定（2026-11-12）与技术方案 §6.4 一致；控制条、设置面板（倍速/比例/网页全屏）、快捷键由播放器提供，站点配置里的播放器开关都能落到 ArtPlayer 选项上 | 播放页 chunk 增到约 744KB（gzip 226KB）；ArtPlayer 与 hls.js 需一起升级 |
| D17 | `customType.m3u8` 内部仍按能力探测：`canPlayType('application/vnd.apple.mpegurl')` 原生优先，否则 hls.js；hls 致命错误销毁后回退原生再试 | iOS/Safari 原生 HLS 更省电、少一层 MSE；桌面 Chrome 走 hls.js | 两套内核行为有差异（如字幕/清晰度），目前片源没有多清晰度 |
| D18 | hls 配置 `{ enableWorker: true, lowLatencyMode: false, maxAudioFramesDrift: 5 }` | 与文档一致；点播不需要低延迟 | — |
| D19 | `parse_url` 含 `{url}` 时替换为 `encodeURIComponent(播放地址)`，否则直接拼接 | 兼容「模板型」与「前缀型」解析接口（文档 §6.1） | 个别源要求不编码，需按源微调时改这里 |
| D20 | 续播用 `localStorage` 键 `lcm:resume:{vodId}:{lineId}`，每 5s 记录、播完清除 | 无登录态，只能本地存；按线路区分避免不同线路时长错位 | 换设备不同步（游客站可接受） |
| D21 | 自动连播仅当 `player_autonext=1`，自动播放仅当 `player_autoplay=1` | 尊重后台开关；浏览器自动播放策略下仍可能被拦截，失败不报错 | 用户可能需再点一次播放 |
| D22 | 播放失败统一文案「该线路暂不支持在线播放」，并允许切线路 | 与文档 §6.4 文案一致 | — |

## 5. 页面交互

| # | 决策 | 理由 |
|---|------|------|
| D23 | 首页三个区块的「更多」按后端 row.title 映射到 `/list/all?sort=time` / `?sort=new`，未知标题回落 `/list/all` | 后端 `more` 仍是 v2 路径（`/today`、`/category/all`），v3 没有这些路由；前端做映射避免改后端 |
| D24 | 列表页每页条数取站点 `listPageSize`（默认 24），分页组件只发 `page`，由页面换算 `skip` | 与后端 `take/skip` 契约一致，且换页大小只需改设置 |
| D25 | 详情页线路切换写回 `?line=`（replace），剧集点击进入播放页 | 详情页可先看线路与剧集，再决定播放；减少一次跳转 |
| D26 | 搜索页 `wd` 为空不发请求，直接展示空态；`noindex` | 后端对空 wd 返回空集，前端不必打接口；搜索页不应被收录 |
| D27 | 封面破图统一回落 `/img/poster-placeholder.svg`；无封面不显示灰块 | 采集源封面缺失很常见 |
| D28 | 剧集一次全渲染（不做分页/虚拟滚动） | 单部影片集数通常 < 200，DOM 压力可接受；原型也是全量 |
| D29 | 页头只显示前 8 个一级分类，其余通过「全部影片」进入列表页筛选 | 分类可达 10+，全放会挤爆导航；与 v2 视觉一致 |

## 6. 明确不做

- 排行、专题、评论、资讯（技术方案 §1.2 已排除）。
- 前台登录/收藏/历史（纯游客站）。
- 统计代码不执行：`site_stats_code` 只随配置返回，不 `innerHTML` 注入（XSS 风险）；如确需统计，应改为后台白名单脚本或独立域。
- 后台「数据处理」页（见 D5）。
- Web 端不做 SSR/预渲染（与技术方案 §4 的 SPA 决策一致）。
