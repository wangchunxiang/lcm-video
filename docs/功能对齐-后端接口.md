### 全局约定（读自源码，非猜测）

- 成功响应统一为 `{ code: 0, msg: 'ok', data: <payload> }`（`apps/server/src/lib/http.ts:17` 的 `ok()`），HTTP 200。
- 失败响应为 `{ code, msg, data: null }`，HTTP 状态码同时生效（`apps/server/src/lib/http.ts:21` 的 `fail()`）。常用 code：`40000` 参数错误、`40100` 未登录/登录失效、`40300` 禁止、`40400` 不存在、`50000` 服务器错误；另有业务码 `40900`（分类被映射占用）、`40902`（最后一条线路）。
- 未匹配路由：`/api/*` 返回 `{code:40400,msg:'接口不存在',data:null}`；`/admin` → 重定向 `/admin/`；其余渲染 404 页面（`apps/server/src/index.ts:137`）。
- 登录态：HttpOnly Cookie `lcm_token`（`apps/server/src/lib/auth-guard.ts:8`），JWT 内带 `uid`、`pv`（密码版本）、`exp`。
- **除认证外的全部 `/api/admin/*` 都挂了 `requireAdmin` preHandler**（`apps/server/src/index.ts:114-115`，前缀 `apps/server/src/index.ts:134`）；`/api/admin/auth/login`、`/logout` 不需要登录，`/api/admin/auth/me` 单独挂 `requireAdmin`。
- `/api/site/*`、`/api/play/*` 不存在（本项目没有独立的 site API 命名空间），前台 JSON 接口只有 `/api/play/:id/:playId/:ep` 与 `/api/play/speed/:vodId/:lineId`。
- 全局后置：`onSend` 注入安全响应头（nosniff / SAMEORIGIN / referrer-policy / permissions-policy / HTTPS 时 HSTS）；`preSerialization` 把 Date 序列化为本地时间字符串；错误统一走 `setErrorHandler`。

### 9.2 筛选参数口径（这是全站唯一的命名，没有第二套）

- 类型：`type`（值为子分类的 `alias`，不是 id；传空等价「全部」）。
- 年份：`year`（四位数字；`0` 或空等价「全部」）。
- 地区 / 语言 / 字母：**没有筛选参数**。前台列表页只提供「类型 / 年份 / 排序 / 页码」四类筛选（模板 `themes/default/list.liquid:13-38`、`themes/default/mobile/partials/filter-sheet.liquid:18-46`）。
- 排序：`sort`，只有 `time`（最近更新，按 `collected_at`）与 `new`（最新入库，按 `created_at`）两值，其他值一律按 `time` 处理。
- 页码：`page`，1 起；`page > 总页数` 时列表页/搜索页返回 **404 页面**（不是空列表）。
- 搜索关键词：`wd`（模板搜索框 `name="wd"`，`themes/default/partials/header.liquid:45`）。

### 9.3 重定向与兼容逻辑

- `/admin` → `302 /admin/`（`apps/server/src/index.ts:142`，为后台 SPA 补斜杠）。
- `/admin/*` 且存在构建产物时，任何未命中路径都回 `index.html`（SPA 前端路由兜底，`apps/server/src/index.ts:144-145`）。
- `/play/ad/:id/:playId/:ep`：广告清洗失败或异常时 `302` 跳回原始播放地址（`apps/server/src/routes/site/index.ts:744`、`750`）。
- **没有旧路径兼容/别名重定向**：没有 `/vod/:id` → `/detail/:id` 之类的历史路径映射，也没有 `?id=` 形式的老入口；未匹配的页面路径一律渲染 404 模板（`apps/server/src/index.ts:147`）。主域名内的 http→https 跳转也不在应用层（依赖前置代理）。

## 十一、盘点中值得注意的结构问题（接口 ↔ 页面耦合 / 多入口）

1. **`/api/admin/sources` 一个前缀被 3 个插件共用**：`sources.ts`（9 条）、`source-categories.ts`（5 条）、`ads.ts`（5 条）分别注册到同一前缀 `/api/admin/sources`（`apps/server/src/index.ts:120`、`124`、`125`）。路径上无法从 URL 判断属于哪个文件，`/:id` 这类通配段在多个插件里语义不同（源站 id / 映射记录 id / 广告特征 id），排查问题必须回源码。
2. **「播放」有三套并行入口，返回形态不一致**：页面 `/play/:id/:playId/:ep`、JSON `/api/play/:id/:playId/:ep`、测速 `/api/play/speed/:vodId/:lineId` 都在 `site` 插件下，但 JSON 接口**不走**统一的 `{code,msg,data}` 包装（后台的广告流式接口 `analyze-stream` 也不走，直接 hijack），而其余 `/api/admin/*` 都走；同一个「换集」动作在前端既可能整页刷新也可能调 JSON 接口，行为由模板决定。
3. **分类的「源站分类映射」与「分类删除」跨域耦合**：删除分类时如果有启用的源站映射会 409（`apps/server/src/routes/admin/categories.ts:157`），必须 `?force=1` 才会顺带把映射重置为未映射；而映射侧又支持 `remap-vods` 直接改写 `vod.categoryId/categoryPid`（`apps/server/src/routes/admin/source-categories.ts:189`），两条链路都能改影片归属，缺少统一入口。
4. **「采集」相关写操作分散在 sources / source-rules / source-categories / cover-check / tools，但都作用于同一批 vod / vod_play**：例如删源站（`apps/server/src/routes/admin/sources.ts:192`）、删源线路（`apps/server/src/routes/admin/tools/data.ts:120`）、清封面（`apps/server/src/routes/admin/cover-check.ts:105`）都会让影片进入「无线路/无封面」状态，前端提示文案与二次确认参数（`force` vs `confirm`）命名不统一。
