| 2.9 | 表的默认接口 | REST，由 `@Crud()` 生成；语义缺口（按条件取唯一一条、取全量）由各自 controller 自写 `@Get('<动作>')`（**目前尚未实现**，`/one`、`/all` 这两个路由不存在） | 调用方只有自家后台，但它给的列表/分页/筛选查询参数比我们手写的更省代码 |
| 3.4 | 裸 SQL 的落点 | 写在用到它的 Service 里，不建单独的 raw 文件 | 一条 SQL 只服务一个业务场景，就近维护比集中更直接 |
| 3.5 | 数据库变更策略 | 三类：可加（新表/可空新列/新索引）、需评估（改类型/缩长度/加唯一约束/删列）、禁止（连库手改结构、绕过迁移的 SQL、改历史迁移） | 旧库烂在没有规矩；实体与迁移是唯一真相源，一切变更留成迁移文件 |
| 3.6 | 连接与事务 | 单个 `DataSource`；事务用 `dataSource.transaction(...)`；采集**每页一个事务**，HTTP 请求在事务外 | 整任务一个事务不可行（全量几万条，失败全回滚）；每页提交让续采从 `last_page` 继续 |

| 4.4 | 旧 URL | 不做 301，旧站直接下线 | 不追求 SEO 迁移，没有必须保住的外链 |
| 4.5 | sitemap / robots | 不做 | 同 4.4 |
| 4.6 | 前端构建 | `apps/web` 与 `apps/admin` 各自 Vite 构建，产物由 server 静态托管 | 两个独立应用，互不打包 |
| 4.7 | 客户端交互 | Vue Router + 统一请求封装；换集/换线路用 `push`，地址规范化用 `replace` | 换集是用户可感知的导航，要能后退；规范化不产生历史记录 |

| 8.2 | 时间序列化 | 统一 ISO 8601 字符串，由拦截器把 `Date` 转成字符串 | 避免同一接口有时字符串有时对象 |
| 8.4 | 文档与注释语言 | 中文 | 现状如此 |

## 2. 由决策推出的约束

### 构建与仓库

NestJS 依赖装饰器元数据（`emitDecoratorMetadata`），Node 24 的类型剥离与 esbuild/tsx 都不提供，必须编译。

- turbo 任务：`build` 依赖 `^build`（`shared` 先于 `server`），`dev` 常驻；根 `npm run check` 依次跑 typecheck / lint / test / build。
- `tsconfig.base.json` 放公共编译选项，各包自己的 `tsconfig.json` 只写差异（`server` 额外开 `experimentalDecorators`、`emitDecoratorMetadata`、`outDir`）。
- 服务端产物在 `dist/`，启动点是编译后的 JS；`Dockerfile` 与 `ecosystem.config.cjs` 都是「先 build、再运行 dist」。
- `packages/shared` 只放纯函数与 DTO 类型（无装饰器、无 IO），编成 CJS + `.d.ts` 供两边消费。
- `packages/api-client` 由接口清单生成/手写，调用 `nest-crud` 的查询协议；不引入运行时依赖。

### 数据模型

- 实体放 `modules/<表>/<表>.entity.ts`，用 `@Entity('lcm_xxx')` 显式指定表名；列名用 `@Column({ name: 'snake_case' })` 对齐库里的下划线命名。
- 所有实体继承 `AppBaseEntity`（`common/crud/app-base.entity.ts`）：`id`（BIGINT UNSIGNED 自增）、`createdAt`、`updatedAt`；`deletedAt` 是无装饰器的幻影字段，只为满足 `nest-crud` 的类型约束，所有控制器统一 `softDelete: false`。
- **主键与引用列一律 `BIGINT UNSIGNED`，JS 侧是字符串**：不做算术、不与数字用 `===`、排序交给数据库。例外只有三类外部标识，保持 `VARCHAR(50)`：`lcm_collect_source_category.source_type_id`、`source_type_pid`、`lcm_vod_play.source_vod_id`（它们是源站的 id，可能与本站主键不同构，空串表示"无"）。
- 表结构的唯一真相源是实体 + `apps/server/src/database/migrations/`。首个迁移是 baseline：按实体从零建表（表注释、字段注释都写进迁移 SQL），并手工补 `CHECK` 约束（`ck_status_mapped` 等 TypeORM 表达不了的部分）。
- **建表自动化**：`config/typeorm.config.ts` 里 `synchronize: false` + `migrationsRun: true`，服务端启动时自动执行未应用的迁移——空库直接建出全部表，已建过的库只跳过。早期 `db:init` 建的老库（有表、没有 `migrations` 表）由 `database/schema-bootstrap.ts` 在启动时登记为已迁移，不会重复建表。
- **实体与迁移用显式清单**（`database/entities.ts`、`database/migrations/index.ts`），不用 `entities: ['**/*.entity.ts']` 这种 glob：glob 在运行时要 `require` 文件，e2e（vitest + swc）下会 require 到 `.ts`，Node 的类型擦除不支持装饰器。新增实体 / 迁移忘了登记会被 `database/entities.test.ts` 挡下。
- 种子 SQL 放 `apps/server/src/database/seeds/`（`lcm_admin_user` / `lcm_category` / `lcm_setting`），由 `npm run db:seed`（`src/database/seed.ts`）导入；内容待从真实库校对。容器部署时 `database/seed-bootstrap.ts` 会在启动、迁移之后按空表自动补 `lcm_category` / `lcm_setting`（`SEED_ON_START=false` 可关），`lcm_admin_user` 为空且配了 `ADMIN_PASSWORD` 时自动建管理员。开发期重建库用 `npm run db:reset`（DROP 全表后按迁移重建，需 `--force`），单独执行迁移用 `npm run db:migrate`。
- `vod.cover_host` 是普通列（不是生成列），索引保留，由业务代码在写封面时维护。
- 不建物理外键：表间关联靠列 + 索引 + 应用层保证。**级联删除也由代码负责**：删影片时在同一个事务里先删它的 `lcm_vod_play`（`VodService.deleteMany` / `delete`），批量删的 `ids` 会先按逗号拆开——`nest-crud` 的 `/delete/bulk` 从 query 取 `ids`，标量会被包成 `['1,2,3']`，不拆就会变成 `IN ('1,2,3')` 删 0 行。删采集源同理：`CollectSourceService.purge()` 在一个事务里按「日志明细 → 日志 → 任务 → 分类映射 / 替换规则 / 广告特征 → 播放地址 → 无线路影片 → 线路注册 → 域名体检 → 源本身」的顺序清（详见 `docs/02-数据库/数据库设计.md` §9）。
- `created_at` / `updated_at` 由 `@CreateDateColumn` / `@UpdateDateColumn` 维护，DDL 上是 `DEFAULT CURRENT_TIMESTAMP(6)` 与 `ON UPDATE CURRENT_TIMESTAMP(6)`；**原生 SQL** 更新行时必须自己补 `updated_at = NOW()`。
- 裸 SQL 用 `dataSource.query(...)` / `repository.query(...)`，参数走占位符数组，不拼字符串；方法上注释说明为什么 QueryBuilder 表达不了。
- 事务写在 Service 方法内，不跨 HTTP 请求；采集按「一页」提交（默认 100 条），不按整个任务提交。
- 网络请求（请求源站、下载页面）一律在事务外；事务内只做写库。

### 对外

- URL 可以重新设计；旧地址不做 301，切换时旧站直接下线。
- 后台功能允许增删与重新设计；盘点文档只用于提示「别漏掉已有能力」，不作为验收标准。

### 契约

- 成功：`{ code: 0, msg: 'ok', data }`。
- 失败：`{ code: 1, msg, data: null }`；需要前端分支时改用专用码（`100401` 登录过期、`100403` 无权限、`100500` 服务端异常）。
- 登录防护分两层，都在 `apps/server/src/common/security/`：
  - **验证码**（`captcha.ts`）：`GET /api/admin/auth/captcha` 生成 4 位字符（去掉 `0/O/1/I/L`）与一张内联 SVG（字符随机旋转/浮动 + 干扰线噪点），答案只留在进程内存，2 分钟过期、最多存 2000 条；登录时带 `captchaId` + `captchaCode`，**校验后立即作废**（同一张图不能重放）。验证码错误回 `code 1`，且**不计入**锁定次数——手滑打错不该把人锁 15 分钟。前端用 `data:image/svg+xml` 塞进 `<img>`（不用 `v-html`），点图换一张，登录失败自动换。
  - **失败锁定**（`login-lock.ts`）：同一 IP 连续 5 次账号密码错误锁 15 分钟，成功即清零。
  - 两者都不落库：单进程部署，重启清零可接受；将来多实例要挪到 Redis。
- 前端判断：`code === 0` 成功；`code === 100401` 清 token 跳登录；其余直接把 `msg` 展示。
- JSON 接口的 HTTP 状态码固定 `200`，不承载语义；前台页面与静态资源不走信封。
- 信封由全局 `ResponseInterceptor` 生成，控制器只返回 `data`；例外用 `@Raw()` 标记（静态资源、NDJSON 流、文件下载）。
- 列表统一 `{ items, total }`，请求参数 `take` / `skip`（`take` 上限 100，**超出直接报错，不截断**：`@ackplus/nest-crud` 抛 `Page size (N) exceeds maxPerPage (100).`，落成 `code: 1` + 英文原文提示。当前没有「不分页取全量」的路由，见「表的默认接口」）。
- 筛选与排序用 `nest-crud` 的查询协议：`where` 为 JSON（操作符 `$eq $ne $gt $gte $lt $lte $like $iLike $in $notIn $between $isNull $isNotNull ...`），`order` 为 JSON（`{"sort":"DESC"}`）。**没有 `$cont`**，模糊匹配写 `$like: "%关键词%"`。
- `nest-crud` 2.5.2 的 `where` 只认实体属性名、却把属性名原样当列名拼进 SQL，属性名与列名不一致时（`sourceId` → `source_id`）会报 `Unknown column`；`common/crud/nest-crud-where.patch.ts` 在启动时把 `WhereQueryBuilder.build` 的 resolver 换成按数据库列名取字段，字段合法性仍按实体属性名校验（传 `snake_case` 依旧被拒）。升级 `nest-crud` 后先确认该 bug 是否已修，再决定是否删掉这个补丁。
- 入参校验走全局 `ValidationPipe`（`whitelist: true`、`transform: true`、`forbidNonWhitelisted: true`），错误信息用 `exceptionFactory` 压成 `字段: 中文提示`。
- 唯一性与存在性在 Service 里预检（`findOne` / `count` 命中即抛 `BadRequestException`），并由实体的唯一索引兜底；不引入第三方校验器。预检与插入之间有竞态，撞唯一键时统一落成 `100500`。
- 时间按**北京时间**存进 `datetime` 列（TypeORM `timezone: '+08:00'`），直接查库看到的就是本地时间；接口返回带 `Z` 的 ISO，前端按浏览器本地时区展示成 `YYYY-MM-DD HH:mm:ss`（`apps/admin/src/utils/datetime.ts`）。前提是 MySQL 会话时区也是 `+08:00`（`SET GLOBAL time_zone = '+08:00'`，持久化写 my.cnf 的 `default-time-zone`），否则 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE` 会写 UTC、与应用写入的时间差 8 小时。v2 旧库本来就存北京时间，导入时原样搬。

### 后台前端

- 列表页三段式固定下来：筛选卡片（`el-card` + `.search-bar`）+ 表格卡片的工具栏 + **`ProTable`**（`apps/admin/src/components/ProTable.vue`）。`ProTable` 负责「撑满高度的表格 + 底部分页 + `el-loading`」，页面只传 `:data` / `:total` / `:page` / `:page-size` / `:loading`，列仍由页面里的 `<el-table-column>` 提供（`#default` 插槽照常可用），选中行回调统一加 `as XxxRow[]` 断言。新增列表页不再手写 `ResizeObserver` 量高度。
- 筛选与分页状态用 **`useTableQuery`**（`apps/admin/src/composables/useTableQuery.ts`）：声明字段默认值即得到 `filters` / `page` / `pageSize` / `search()` / `reset()`，读写 `route.query`（只写非默认值，`router.replace`，比较字符串后写入），刷新、后退、贴链接都能还原。页面自己负责在 `search()` 外层补 `load()`。
- 批量删除走 **`bulkDelete`**（`apps/admin/src/utils/bulk.ts`）：逐个 `DELETE /api/admin/<表>/:id` 并用 `Promise.allSettled` 汇总，**不要**用 `nest-crud` 的 `DELETE /delete/bulk?ids=1,2,3` —— 它把 query 标量包成 `['1,2,3']` 后拼 `IN ('1,2,3')`，删 0 行却返回成功。服务端的 `VodService.deleteMany` 为此额外把 `ids` 按逗号拆开。
- 可能超过 30 秒的接口走 **`api.longPost` / `api.longGet`**（`timeoutMs: 0`）：采集源拉分类、广告识别流、封面体检扫描、采集任务执行、单条重采。
- 路由全部懒加载（菜单地址 → `() => import()`），未实现的菜单项回落到 `Placeholder.vue`，另有 `:pathMatch(.*)*` → `NotFound.vue` 兜底。
- Element Plus 由 `unplugin-vue-components` 按需注入（`apps/admin/vite.config.ts`），`main.ts` 只手动引命令式 API 的样式（message / message-box / loading / notification）+ `styles/global.css`；图标按需 `import { Xxx } from '@element-plus/icons-vue'`，不再全局注册。迁移时踩过：`Components({ dts: false })` 必须关掉类型声明生成，否则 `el-table` 插槽按 `DefaultRow` 校验，和「行类型写明」的写法冲突（一次冒出上百个 `TS2345`）。

### 表的默认接口

`@AppCrud({ entity, path: '<表>', dto })` 生成标准 REST 路由。**`path` 只写资源名**（如 `'vod'`、`'category'`），前缀 `/api/admin` 由装饰器拼（`common/http/api-prefix.ts` 的 `ADMIN_API_PREFIX`），写成 `'api/admin/vod'` 会得到 `/api/admin/api/admin/vod`。项目默认值集中在 `common/crud/app-crud.decorator.ts`：不软删（`softDelete: false`，`restore` / `deleteFromTrash` 四条回收站路由随之自动关闭）、`maxPerPage: 100`、关掉 `createMany` 与 `reorder`；控制器里只写 `entity` / `path` / `dto` 等差异项。

| 动作 | 方法与路径 | 语义 |
|---|---|---|
| 列表 | `GET /api/admin/<表>` | 支持 `where` / `order` / `take` / `skip` / `select` / `relations`；返回 `{ items, total }` |
| 单条 | `GET /api/admin/<表>/:id` | 按主键取 |
| 新建 | `POST /api/admin/<表>` | 返回创建后的实体 |
| 更新 | `PUT /api/admin/<表>/:id` | 局部更新 |
| 删除 | `DELETE /api/admin/<表>/:id` | 硬删除（`softDelete: false`） |

补充路由（`nest-crud` 不覆盖的语义，写在同一个 controller 里）：

目前**尚未实现**：全仓没有 `@Get('one')` / `@Get('all')`，`AppCrudService` 也没有 `all` / `one` 方法。需要「按条件取唯一一条」或「取全量」时，在目标表的 controller 里用 `@Get('<动作>')` 自写，不要照 v1 的 `/one`、`/all` 约定去调——那些路由会 404。

- 批量操作、跨表联动写在主表 controller 里，路径同样是 `/api/admin/<表>/<动作>`，不新建无表目录。
- 内部表（`setting`、`admin-user`、`collect-task-log-detail` 等）同样按上表开；`admin-user` 的响应 DTO 不含密码字段。
- NDJSON 流走 `@Raw()`，不受信封约束。

### 前台

前台是与后台同构的独立 SPA，服务端不再渲染任何 HTML。

```
apps/web      Vue 3 + Vue Router + ArtPlayer（自绘样式，不引 Element Plus）
apps/server   /api/web/* 公开 JSON；其余路径回落 index.html
```

- 页面与路由：`/` 首页、`/list`（跳第一个一级分类）、`/list/:alias` 分类列表、`/detail/:id` 详情、`/play/:id/:lineId?/:ep?` 播放、`/search` 搜索、`/:pathMatch(.*)*` 404。
- 站点配置（`GET /api/web/config`）与分类树（`GET /api/web/categories`）由 `site.ensureSite()` 全局只拉一次；列表/搜索页等 `site.ready` 再发查询，路由守卫也等它（`/list` 要按第一个一级分类重定向）。
- 请求可中断：`portal.*` 都接受 `{ signal }`，页面切换/重新筛选时 abort 上一个请求；`@lcm/api-client` 默认 30 秒超时，长任务接口显式传 `timeoutMs: 0`。
- 弹窗锁滚动统一用 `composables/useScrollLock.ts`：组件卸载时复位 `body.overflow`，开着弹窗离开页面不会把全站锁死。
- 首页只有「今日更新」一段：`GET /api/web/home` 按 `collected_at >= CURDATE()` 取 **16 部**（`apps/server/src/modules/portal/portal.service.ts` 的 `HOME_ROW = 16`），命中 `idx_status_collected`，不做「最新收录 / 最近热播」这类全表排序。卡片头显示的是**当天总数**（同一 where 的 `COUNT(*)`，`rows[0].total`），不是被截断后的 16；`items` 只带前 16 部用于 8 列 × 2 行网格。
- 筛选与播放位置全部放 query：`/list/:alias?type=&year=&sort=&take=&skip=`；`/play/:id` 的第二段是 `lcm_vod_play.id`，前端用 `findIndex` 换算成接口要的 0 基 `line` 下标，再用 `router.replace` 规范化地址。
- 列表分页参数前后端一致用 `take`/`skip`（默认 24，上限 100）。
- 换集与换线路都用 `router.push`（可后退），只有地址规范化用 `router.replace`；`scrollBehavior` 对**同一路由名**（`detail` / `play`）返回 `false`，保持滚动位置，只有跨页面导航才回顶部。
- 直链播放走本站的**播放列表代理** `GET /api/web/playlist`（`/api/web/play` 返回的 `episodes[].playUrl`）：代理按该源已确认的广告特征删掉分片再返回 m3u8；没命中广告也返回正文（逐行绝对化后的原文，只是不做删减；master 播放列表照样回 master，不会下钻成单条变体，否则自适应码率与分离音轨会丢），**不再 302 回源**——Apple 原生播放器对 media 请求的重定向很脆弱，源站常常自己还要再跳一次，多一跳就多一次偶发失败。上游拉取失败（超时/报错，另有 2MB 体积上限）直接回 **502**，不再把播放器甩回源站——那条跳转链正是 iOS 偶发失败的地方。地址带 HMAC 签名（`portal/playlist-proxy.ts`，密钥复用 `JWT_SECRET`），不是本服务签出的一律 403，避免变成开放代理。该源一条广告特征都没有时 `play` 不包这一层，`playUrl` 等于源地址。上游拉取失败不降级直连，而是明确报错并写一条 warn 日志，便于统计失败率。只有上游自身的失败算 502（`UpstreamPlaylistError`），DB/代码错误照常 500，不把故障混成「源站抽风」。
- 换集是**就地切源**：只改 `current`，`PlayerBox` 调 `art.switchUrl()`，不再请求 `/api/web/play`，也不销毁 ArtPlayer（不再黑一下）；换线路要先拉一次该线路的剧集列表，再就地切源并保持当前集数（新线路集数不够才回落）。
- 播放内核判定：给 ArtPlayer 的 `type` 一律由 `inferType(url)` 算（`apps/web/src/components/PlayerBox.vue`）——地址走本站播放列表代理 `/api/web/playlist`、或后缀是 `.m3u8` 时给 `'m3u8'`，其余给 `''`；就地换集前还要按新地址重算一次 `art.option.type`（artplayer 的 url setter 读的是 `option.type || 后缀推断`）。写死 `'auto'` 会去查不存在的 `customType['auto']`；只靠后缀推断也不行——去广告代理的地址是 `/api/web/playlist?...`，既没后缀又带查询串，推出来的类型不在 `customType` 里，hls.js 永不加载，Chrome/Firefox 把 m3u8 裸塞给 `video.src` 只得 `MEDIA_ERR_SRC_NOT_SUPPORTED (4)`，界面就是「该线路暂不支持在线播放」，且**控制台不会有任何 JS 报错**。iPhone/iPad 没有 MSE，直接走原生。
- 设备级偏好存 `localStorage`：续播 `lcm:resume:{vodId}:{lineId}:{ep}`（每 5s 记、播完清、换集前强制写一次）、自动连播 `lcm:autonext`（默认取 `player_autonext`）、选集正序/倒序 `lcm:ep-order`。
- 选集切完把当前集滚到容器中间：用 `getBoundingClientRect` 差值算位移（`offsetTop` 在卡片里会算偏）。
- 详情页「立即播放」右侧是「手机观看」：点开用 `window.location.href` 生成二维码（`qrcode-generator`，`qrcode(0, 'M')` + `createSvgTag({ scalable: true })`，只给 `viewBox` 不给宽高）。该库的 ESM 构建里没有 `stringToBytesFuncs['UTF-8']`，必须在模块作用域覆盖 `qrcode.stringToBytes` 用 `TextEncoder` 编码，否则 `?wd=中文` 这类地址会被按 latin1 截断成乱码。
- 详情页切线路只改页面状态、不写 URL（地址始终是 `/detail/:id`）；搜索页 `wd` 为空不发请求直接出空态，并 `noindex`；页头只放前 6 个一级分类（`apps/web/src/components/SiteHeader.vue` 的 `site.categories.slice(0, 6)`），其余进列表页筛选。
- 封面破图统一回落 `/img/poster-placeholder.svg`，无封面不显示灰块；剧集一次全渲染，不做分页/虚拟滚动（单部通常 < 200 集）。
- **不做**：排行、专题、评论、资讯；前台登录/收藏/历史（纯游客站）；SSR/预渲染；`site_stats_code` 不 `innerHTML` 注入（XSS 风险，只随配置返回）。
- 静态回落与 `/api` 分流由服务端中间件完成；v1 的 `themes/` 目录已删除，品牌资源（favicon、icon、logo、占位图）移到 `apps/web/public/`。
- 静态资源缓存：`/assets/` 下文件名带内容哈希，回 `Cache-Control: public, max-age=31536000, immutable`；`index.html` 等固定名字一律 `no-cache` 回源校验（`apps/server/src/main.ts` 的 `staticCache()`）。`index.html` **不能** 给正数 `max-age`：发版后浏览器会拿着旧页面去要旧哈希的 chunk，服务端对带扩展名的 404 回的是 JSON 信封，动态 import 直接失败。播放失败态（`failed`）只在画面上叠一句提示，不放按钮，避免和播放器自带控件重叠。
- 播放器用 ArtPlayer 5：`customType.m3u8` 内部探测原生 HLS 与 hls.js，主题色 `#3b82f6`（= `--primary`），不传 `poster`（加载中保持黑底）；Element Plus 只用于后台。

### 后台概览

首页「数据概览」是一屏看板，回答三件事：**现在健康吗 / 趋势往哪走 / 我要不要动手**。因此它没有「最近入库」这类浏览类内容（要看新片去影视管理按入库时间排序），「最近采集」也只压成一句话（「12 分钟前 · 天堂资源」）。

- 布局：KPI 四卡一行，下方是**八等分栅格**（`repeat(8, minmax(0,1fr))` + 12px gap）的两行——第一行 `分类影片数` 饼图（2 格）+ `今日采集`（6 格），第二行 `线路分布`（2 格）+ `今日更新`（3 格）+ `今日入库`（3 格）。八等分是为了同时满足两件事：左列 2 格恰好等于顶部一张 KPI 卡的宽度（竖线、右边缘都对得上），第二行剩下 6 格能被两张列表平分。改宽度只改这一处 `grid-template-columns`，别另写固定 px。整页吃满 `el-main` 不滚动，超长只在卡片内部滚（`grid-template-rows: repeat(2, minmax(0,1fr))` 配 `min-height: 0`）。
- `线路分布` 的后端也返回**全部**线路（`lcm_vod_play` 按 `source_from` 聚合，按地址数倒序），卡片里是可滚动列表，滚动条与 `今日更新`/`今日入库` 同一套 `.feed-body` 样式；上面的堆叠条只画前 4 段（段数再多就认不出颜色），第 5 条起并成灰色「其他 N 条」。
- `今日更新` / `今日入库` 都是**当天**的滚动列表（`WHERE updated_at >= CURDATE()` / `WHERE created_at >= CURDATE()`，各取前 50 条，多的在卡片里滚），卡头显示当日总条数。入库按主键倒序（与写入顺序一致、走主键扫描），更新按 `updated_at` 倒序（靠 `idx_updated_at`）。
- **一张图就是一个采集维度**：`inserted / updated / ignored / failed / skipped` 五种去向固定同色同序（前端的 `DIMENSIONS` 常量），今日采集按 24 小时画折线，构造在 `dimensionLines()` 里。新加维度只要改 `DIMENSIONS` 与后端那几条 `SUM()`。**「跳过」排在图例最后且默认关闭**（`LEGEND_DEFAULT`）：它一次运行 59~100，而新增/更新只有个位数到几十，共用一根 Y 轴时会把它俩压成底部一条线；点图例即可打开。
- 被删掉的三块（都因为占着版面却没提供独有信息）：13 周热力图（与「今日采集」重复）、`数据新鲜度` 卡（只报一个成功率与三个时间）、`源站健康` 卡与 `待处理` 清单（待处理汇总已进顶部第四卡，点数字去对应页面）。再想加卡片先问「它回答的问题别处有没有答案」。
- 图表：今日采集与饼图用 ECharts，按需注册收在 `apps/admin/src/utils/echarts.ts`（`echarts/core` + `LineChart` + `Grid/Tooltip/Legend` + `CanvasRenderer`），并在 `apps/admin/vite.config.ts` 的 `optimizeDeps.include` 里列全，避免 dev 下第一次进首页重新预打包导致整屏刷新；图表组件走 `defineAsyncComponent`，首屏不背 echarts 那 180KB。新增图表先在 `utils/echarts.ts` 里 `use`，不要在组件里重复注册（`<script setup>` 顶层每个实例都会跑）。
- 分类饼图只取**一级分类**（`WHERE c.pid = 0`），按在架影片数排前 6、长尾并成「其他 N 个」：一级分类有二十来个，全画进饼图看不清。所以后端 `categories()` 返回**全部**一级分类而不是 Top6，前端 `CATEGORY_SLICES` 决定切几块。
- 只有一个接口 `GET /api/admin/dashboard/summary`，一次拼一屏，避免首屏发七八个请求。
- **形状固定**：`hours` 恒为 24 项、`trend` 恒为 8 项（今天往前推 7 天 + 今天），缺数据的补 0。折线按索引取点，少一格就会错位。曲线上不再画趋势图，但 `trend` 仍保留——顶部第一张卡的「+N / 7 天」就是它求和得来的；改窗口只动 `TREND_DAYS`，点数由 `TREND_POINTS = TREND_DAYS + 1` 推出。
- **口径：只统计增量采集**。`lcm_collect_task_log.range_type = 4` 是「全部」（手动采集一个源站就是它，一次性把整站拉下来，实测一次能写 6 万行）；今日采集、趋势、源站 sparkline 与今日入库/更新/跳过/忽略/失败都按日志自己的 `range_type` 快照排除它，只留每日采集的增量。反例：不排除时全量那一跑会把当天柱子顶成平地起尖，曲线失去意义。今日「运行次数」仍算全部运行（全量也是一次运行），所以 `hours[].runs` 用 `COUNT(*)`，而它旁边那五个量用 `SUM(CASE WHEN range_type <> 4 ...)`。
- 聚合值一律 `Number()` 收口：mysql2 把 `SUM()` 返回成字符串，混进前端做除法会变成字符串拼接（趋势柱高度直接变成 `NaN` 或离谱值）。
- 线路名取 `COALESCE(NULLIF(lcm_play_line.name, ''), source_from)`：线路注册表只是显示覆盖层，没注册的线路照样有播放地址，回退到线路标识。
- 待处理口径：图片只数 `lcm_cover_check.status IN (2, 3)`（1 正常、0 未检查都不算异常）；重复影片与「重复影片」页同口径（`GROUP BY name_hash HAVING COUNT(*) > 1 AND MIN(NULLIF(year, 0)) <=> MAX(NULLIF(year, 0))`），**不要**调该页的 `preview()`（1.2 秒）；「影片没有播放地址」用 `NOT EXISTS` 反查播放行；失败日志 = `status = 3` 且不设时间窗。
