# 蓝草莓影视 · 技术方案

一个精简版苹果CMS式采集影视站：从资源站采集影片 → 入库去重 → 前台展示与播放 → 后台管理。

---

## 1. 定位与功能范围

### 1.1 定位

- **单站**：一个域名、一套数据。
- **PC 优先**：第一版只保证桌面端体验，移动端适配放到二期。
- **纯游客**：无注册、登录、收藏、历史；需要记忆的状态走浏览器本地存储。

### 1.2 前台页面

| 页面 | 内容 |
|---|---|
| 首页 | 最新更新、分类入口 |
| 分类列表页 | 筛选（类型 / 年份 / 排序）、分页 |
| 详情页 | 简介、演员/导演、剧集列表 |
| 播放页 | 线路切换、剧集切换 |
| 搜索页 | 片名 |

不做：排行榜、专题合集、留言评论、文章资讯。

### 1.3 后台模块

| 模块 | 范围 |
|---|---|
| 登录 | 单管理员账号，可改密码 |
| 数据概览 | 影片总数、今日新增、最近一次采集结果 |
| 采集源站 | 增删改、测试连通性、启用停用；配置解析接口地址 |
| 替换规则 | 按源站配置播放地址与图片地址的前缀替换，采集时自动套用，可重刷存量 |
| 采集任务 | 手动触发、定时执行 |
| 采集记录 | 存库，保留 30 天，可翻页查看明细 |
| 分类映射 | 采集源分类 → 本站分类 |
| 分类管理 | 两级树、排序、是否显示、URL 别名 |
| 影视管理 | 列表筛选、编辑、上下架、批量改分类/上下架/删除；编辑页含线路与剧集，并带"批量替换播放地址" |
| 播放管理 | 播放设置（自动播放/连播/进度记忆、控制栏按钮开关）、线路设置（全站线路的显示名、排序、启停） |
| 系统设置 | 站点设置、账号设置 |
| 高级工具 | 与系统设置平级的一级入口 |

约束：**新增影片只有采集一个入口**，不提供手工新建。

影视管理的「删除」实际是下架：影片保留在库，`status` 置 0。采集不回改上架状态，被下架的影片不会被重新采集上架。

### 1.4 影片编辑范围

标题、副标题、分类、年份、地区、语言、演员、导演、简介、封面、状态，以及线路与剧集。

剧集编辑：按线路分组的表格，每行"序号 / 名称 / 地址"，可增删改、上下移动，支持整段粘贴批量导入。

### 1.5 权限

单角色，超级管理员一人一账号。

### 1.6 后台菜单

```
数据概览
采集管理
  ├ 采集源站
  ├ 替换规则   ← 源站的播放/图片地址前缀替换
  ├ 分类映射
  ├ 采集任务
  └ 采集记录
内容管理
  ├ 影视管理
  └ 分类管理
高级工具
  ├ 数据处理
  ├ 重复影片
  └ 图片检查
播放管理
  ├ 播放设置   ← 播放行为与控制栏按钮开关
  └ 线路设置   ← 全站线路的显示名、排序、启停
系统设置
  ├ 站点设置   ← 站点名称、副标题、logo、favicon、免责声明、统计代码、模板选择
  └ 账号设置   ← 用户名、密码、登录有效期
```

- 解析接口地址在采集源表单中配置；播放行为与控制栏按钮在播放设置里配置。
- 模板启用是站点设置里的一个选项，只做启用与文件列表，不做在线编辑。
- 线路与剧集在影视管理编辑页内维护，不设独立菜单。

## 3. 技术架构与工程结构

### 3.1 工程结构

包管理工具用 npm（npm workspaces）。

```
lcm-video/
├─ apps/
│  ├─ server/          Fastify：前台 SSR + 后台 API
│  └─ admin/           Vue 3 + Element Plus 后台前端
├─ packages/
│  ├─ db/              Drizzle schema、迁移、连接池
│  └─ shared/          前后端共用的类型与常量
├─ themes/
│  └─ default/         前台 Liquid 模板与静态资源
├─ docs/
└─ package.json        workspaces: apps/*, packages/*
```

### 3.2 服务端内部分区

前台页面与后台接口按目录分开，各自的入口互不引用。

```
apps/server/src/
├─ index.ts            启动装配：插件 → 路由
├─ env.ts              环境变量读取与校验
├─ plugins/            数据库、模板引擎、静态资源、鉴权、错误处理
├─ routes/
│  ├─ site/            前台站点页面（SSR 渲染）
│  └─ admin/           后台接口
├─ services/           业务逻辑：采集、影片、分类、设置
└─ lib/                通用工具
```

- 后台接口统一挂 `/api/admin/*` 前缀，与前台路径不交叉。
- 前台是页面路由，不带 API 前缀：`/`、`/list/:alias`、`/detail/:id`、`/play/:id/:playId/:ep`、`/search`。SSR 直接查库渲染，不经 HTTP 自调。
- 前台不需要 `/api/site`；二期若出现搜索联想一类 AJAX 需求，再单独开这个前缀。
- 前台路由只负责取数与渲染，业务逻辑落在 `services/`。

### 3.3 进程与托管

- **开发**：两个进程。Fastify 3100 提供前台 SSR 与 `/api/admin`；Vite 3200 跑后台，`/api` 代理到 3100。
- **生产**：一个 Fastify 进程。同时提供前台 SSR、`/api/admin/*`、后台构建产物（挂 `/admin`，SPA 路由回退到 `index.html`），以及上传目录的静态访问。
- 前台是 SSR，不是前后端分离；后台是 SPA，属于前后端分离。开发期的两个进程只是 Vite 的工具链，生产对外只有一个进程、一个端口。
- 后台构建产物的资源路径以 `/admin/` 为基准（Vite `base: '/admin/'`），否则生产环境静态资源全部 404。

### 3.4 TypeScript 运行方式

- 全项目 TypeScript + ESM，靠 Node 24 原生类型擦除直接运行，不构建。
- 不使用 `enum`、`namespace`、参数属性、装饰器；导入路径写带扩展名的相对路径。
- `tsc --noEmit` 只做类型检查，不产出文件。
- 启动命令统一写在 3.5，本节不再重复。`.env` 固定在仓库根，服务端从 `apps/server` 目录内启动，用 `--env-file=../../.env` 指过去。

### 3.5 开发命令

根目录 `package.json`：

```json
{
  "scripts": {
    "dev": "concurrently -n server,admin -c cyan,green \"npm:dev:server\" \"npm:dev:admin\"",
    "dev:server": "npm run dev -w apps/server",
    "dev:admin": "npm run dev -w apps/admin",
    "build": "npm run build -w apps/admin",
    "typecheck": "tsc --noEmit",
    "db:generate": "npm run generate -w packages/db",
    "db:migrate": "npm run migrate -w packages/db"
  }
}
```

`apps/server/package.json`：

```json
{
  "scripts": {
    "dev": "node --watch --env-file=../../.env src/index.ts",
    "start": "node --env-file=../../.env src/index.ts"
  }
}
```

- `npm run dev` 一次启动服务端 3100 与后台 3200，日志带 `[server]` / `[admin]` 前缀。
- 需要分开看日志时，开两个终端分别跑 `dev:server`、`dev:admin`。
- `concurrently` 只作开发依赖，不进生产依赖。

### 3.6 后台界面约定

- 默认使用 Element Plus 的组件与样式；组件已经表达的状态（选中、禁用、加载、校验错误）不重复叠加装饰。
- 允许的装饰限于表达信息或布局需要：状态色用 EP 的 `type`（success/warning/danger/info）、分组标题、说明文字、区块底色、必要的分隔线与间距。
- 不允许纯视觉装饰：渐变、阴影、额外圆角、重复的选中底色、自定义高亮色。
- 需要跟随主题的颜色改 EP 的 CSS 变量（如 `--el-menu-bg-color`），不用组件上颜色属性的写法。
- 页面样式以布局为主：间距、宽度、对齐、栅格。

## 4. 数据库设计

### 4.1 通用约定

- 表名统一 `lcm_` 前缀。
- 每表主键 `id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT`。
- 每表带 `created_at`、`updated_at`，均为 `DATETIME`，默认 `CURRENT_TIMESTAMP`，`updated_at` 带 `ON UPDATE`。
- 时间字段统一用 `DATETIME`，不用 int 时间戳。
- 所有表 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`。
- 不建外键，级联关系由程序维护。

### 4.2 表清单

| 表 | 用途 |
|---|---|
| `lcm_category` | 分类，两级 |
| `lcm_vod` | 影片主表 |
| `lcm_vod_play` | 播放线路，一条线路一行 |
| `lcm_collect_source` | 采集源站 |
| `lcm_collect_source_category` | 源站分类与本站分类的映射 |
| `lcm_source_rule` | 采集源的地址替换规则 |
| `lcm_play_line` | 全站线路注册表，决定前台线路顺序 |
| `lcm_collect_task` | 采集任务 |
| `lcm_collect_log` | 采集记录，一次采集作业一行（续采不新增），保留 30 天 |
| `lcm_collect_log_detail` | 采集记录明细，一页一行 |
| `lcm_ad_feature` | 去广告的时长特征 |
| `lcm_cover_check` | 图片域名体检结果 |
| `lcm_vod_merge_ignore` | 重复影片的人工忽略标记 |
| `lcm_admin_user` | 后台账号 |
| `lcm_setting` | 站点与程序配置 |

### 4.3 lcm_category

```sql
CREATE TABLE `lcm_category` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `pid`         BIGINT UNSIGNED NOT NULL DEFAULT 0        COMMENT '父分类ID，0=顶级',
  `name`        VARCHAR(50)    NOT NULL DEFAULT ''        COMMENT '分类名称',
  `alias`       VARCHAR(50)    NOT NULL DEFAULT ''        COMMENT 'URL别名，仅小写字母数字减号，必填',
  `match_names` VARCHAR(255)   NOT NULL DEFAULT ''        COMMENT '采集匹配名，英文逗号分隔',
  `sort`        INT UNSIGNED   NOT NULL DEFAULT 0         COMMENT '排序，越小越前',
  `is_show`     TINYINT UNSIGNED  NOT NULL DEFAULT 1      COMMENT '1显示 0隐藏',
  `created_at`  DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_alias` (`alias`),
  KEY `idx_pid_sort` (`pid`,`sort`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- `pid` 只允许两层，由程序校验。
- `alias` 必填且唯一，只允许小写字母、数字、减号。保存时校验，重复即拒绝。
- 分类页地址走 `alias`：`/list/{alias}`，见 7.3。修改 `alias` 后旧链接失效，不做 301。
- `is_show = 0` 只影响前台显示，不影响采集入库。
- 有子分类或分类下仍有影片时禁止删除，提示剩余数量。
- 采集匹配时按 4.7 的规则使用 `match_names`。

### 4.4 lcm_vod

```sql
CREATE TABLE `lcm_vod` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `category_id`   BIGINT UNSIGNED NOT NULL DEFAULT 0       COMMENT '分类ID，映射到一级或二级分类',
  `category_pid`  BIGINT UNSIGNED NOT NULL DEFAULT 0       COMMENT '父分类ID，冗余；分类为一级时为 0',
  `name`          VARCHAR(255)   NOT NULL DEFAULT ''       COMMENT '标题，存归一化后的值',
  `name_hash`     CHAR(32)       NOT NULL DEFAULT ''       COMMENT '归一化名称的 MD5，判重用',
  `sub_name`      VARCHAR(500)   NOT NULL DEFAULT ''       COMMENT '副标题',
  `letter`        CHAR(1)        NOT NULL DEFAULT ''       COMMENT '首字母，A-Z 或 0-9，其余存空',
  `cover`         VARCHAR(500)   NOT NULL DEFAULT ''       COMMENT '封面，源站完整 URL',
  `actor`         VARCHAR(1000)  NOT NULL DEFAULT ''       COMMENT '演员',
  `director`      VARCHAR(500)   NOT NULL DEFAULT ''       COMMENT '导演',
  `writer`        VARCHAR(500)   NOT NULL DEFAULT ''       COMMENT '编剧',
  `intro`         VARCHAR(1000)  NOT NULL DEFAULT ''       COMMENT '简介，列表用',
  `content`       TEXT                                    COMMENT '详细介绍',
  `remarks`       VARCHAR(255)   NOT NULL DEFAULT ''       COMMENT '备注，如 更新至20集',
  `release_date`  VARCHAR(255)   NOT NULL DEFAULT ''       COMMENT '上映日期，仅展示',
  `episode_count` INT UNSIGNED   NOT NULL DEFAULT 0        COMMENT '总集数，源站声明',
  `area`          VARCHAR(100)   NOT NULL DEFAULT ''       COMMENT '地区',
  `lang`          VARCHAR(100)   NOT NULL DEFAULT ''       COMMENT '语言',
  `year`          INT UNSIGNED   NOT NULL DEFAULT 0        COMMENT '年份',
  `status`        TINYINT UNSIGNED  NOT NULL DEFAULT 1     COMMENT '1上架 0下架',
  `collected_at`  DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '最后采集时间，取所有线路的最大值',
  `created_at`    DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`    DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_category_status` (`category_id`,`status`),
  KEY `idx_pid_status` (`category_pid`,`status`),
  KEY `idx_letter` (`letter`),
  KEY `idx_name_hash` (`name_hash`),
  KEY `idx_status_collected` (`status`,`collected_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- `episode_count` 是源站声明的总集数，与 `lcm_vod_play` 里实际剧集数不互相覆盖。
- 不存评分。
- `name` 存归一化后的值，`name_hash` 为 `md5(name)`，由程序在写入时同步计算，见 §5.2。
- `collected_at` 是冗余字段，供前台「最近更新」排序使用。写入线路时同步更新：`UPDATE lcm_vod SET collected_at = GREATEST(collected_at, ?) WHERE id = ?`。

### 4.5 lcm_vod_play

```sql
CREATE TABLE `lcm_vod_play` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `vod_id`      BIGINT UNSIGNED NOT NULL                   COMMENT '影片ID',
  `source_id`   BIGINT UNSIGNED NOT NULL DEFAULT 0         COMMENT '采集源ID，0=手工添加',
  `source_from` VARCHAR(50)    NOT NULL DEFAULT ''         COMMENT '源站返回的线路标识，如 lzm3u8；手工线路填自定名称',
  `source_vod_id`     VARCHAR(50)    NOT NULL DEFAULT ''   COMMENT '源站影片ID',
  `source_updated_at` DATETIME       NULL DEFAULT NULL     COMMENT '源站标注的更新时间',
  `collected_at`      DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '本线路最后采集时间',
  `play_url`    MEDIUMTEXT     NOT NULL                    COMMENT '整条线路的剧集串，原样存',
  `created_at`  DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_vod_source_from` (`vod_id`,`source_id`,`source_from`),
  KEY `idx_source` (`source_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- 一条线路一行，剧集全部装在一个字段里，格式 `名称$地址#名称$地址#…`，按源站返回原样存。
- 写入前先在内存里判定该线路是否需要更新：同键线路不存在则 `INSERT`；存在且新集数 ≥ 旧集数则 `UPDATE play_url`；存在且新集数 < 旧集数则跳过。不做无条件 UPSERT，规则见 §5.3。
- `source_from` 是内部键，不对用户展示；前台线路名由 `source_id` 关联采集源表的 `name` 得到，`source_id = 0` 时直接显示 `source_from`。
- `source_id = 0` 的手工线路不受删源清理影响。
- `source_vod_id`、`source_updated_at`、`collected_at` 是按源记录的采集信息，同一源提供的多条线路会各存一份。
- 增量采集按线路判断：源站本次返回的 `vod_time` 与该线路的 `source_updated_at` 相同则跳过剧集重写，不同则更新剧集并刷新 `source_updated_at`。
- 后台「重新采集单片」按线路的 `source_vod_id` 请求源站详情接口。

### 4.6 lcm_collect_source

```sql
CREATE TABLE `lcm_collect_source` (
  `id`               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `name`             VARCHAR(50)    NOT NULL DEFAULT ''       COMMENT '源站名称，前台线路显示用',
  `api_url`          VARCHAR(255)   NOT NULL DEFAULT ''       COMMENT '采集接口地址',
  `api_format`       VARCHAR(10)    NOT NULL DEFAULT 'json'   COMMENT '接口类型 json / xml（当前不参与请求）',
  `api_params`       VARCHAR(500)   NOT NULL DEFAULT ''       COMMENT '接口额外参数，如 t=1；不许写 ac/pg/pagesize/at/h',
  `parse_url`        VARCHAR(255)   NOT NULL DEFAULT ''       COMMENT '解析接口地址，空=直连播放',
  `is_enabled`       TINYINT UNSIGNED NOT NULL DEFAULT 1      COMMENT '1启用 0停用',
  `interval_sec`     INT UNSIGNED   NOT NULL DEFAULT 3        COMMENT '两次请求的间隔秒数',
  `pagesize`         INT UNSIGNED   NOT NULL DEFAULT 100      COMMENT '每页条数，1-100',
  `timeout`          INT UNSIGNED   NOT NULL DEFAULT 30       COMMENT '超时秒数',
  `retry_times`      TINYINT UNSIGNED NOT NULL DEFAULT 2      COMMENT '失败重试次数',
  `last_sync_at`     DATETIME       NULL DEFAULT NULL         COMMENT '最后同步时间',
  `last_sync_status` TINYINT UNSIGNED NOT NULL DEFAULT 0      COMMENT '0未同步 1成功 2失败',
  `last_sync_msg`    VARCHAR(255)   NOT NULL DEFAULT ''       COMMENT '最后同步结果说明',
  `created_at`       DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`       DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_enabled` (`is_enabled`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- `parse_url` 为空时前台用原生 `<video>` + hls.js 播放，有值时用 iframe 套解析页。
- 后台列表按 `created_at` 倒序，不设排序字段。
- 前台线路顺序由全局配置项 `line_order` 决定，见 §6.2。
- 采集执行先后由采集任务决定。
- `pagesize` 是请求列表接口时每页的条数，默认 100，取值范围 1-100。部分源站不支持 100 时可调小。
- `api_params` 是原样拼到接口地址后面的查询串，`ac`、`pg`、`pagesize`、`at`、`h` 由程序控制，不允许出现在这里；保存时校验，出现即拒绝。
- `interval_sec` 是同一源站两次请求之间的等待秒数，默认 3。计时从上次请求结束到下次请求开始。
- 封面图不使用相对路径，无需前缀配置。

### 4.7 lcm_collect_source_category

```sql
CREATE TABLE `lcm_collect_source_category` (

  `updated_at`       DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_source_type` (`source_id`,`source_type_id`),
  KEY `idx_category` (`category_id`),
  KEY `idx_source_status` (`source_id`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- 本表保存从源站获取的分类清单及其映射结果，每个采集源一套，靠 `source_id` 隔离。
- 映射认 `source_type_id`，源站改名不丢映射，只更新 `source_type_name`。
- **数据来源**：后台「分类映射」页点「获取分类」时请求源的 `ac=list`，把 `class[]` 整体 UPSERT 进来，已有映射结果不覆盖。
- **状态**：`1` 已映射，采集时用 `category_id` 入库；`2` 已忽略，该分类下的影片跳过；`0` 未映射，先自动匹配一次，仍未命中则跳过不入库。
- **匹配方式**：`match_type` 记录映射来源，`0` 无、`1` 自动、`2` 手动。`match_type = 2` 的记录后续获取分类不会被自动覆盖。
- **自动匹配只做两步**，命中即写 `category_id`、`match_type = 1`、`status = 1`：
  1. `lcm_category.match_names` 命中源站分类名；
  2. 名称与源站分类名完全相等。
- **未自动匹配的分类留空**，由人工在目标下拉里选择，写入 `match_type = 2`。不做包含匹配，也不做候选提示。
- **不继承**：父分类映射后，子分类仍需单独映射；未映射的子分类下的影片跳过。
- **映射目标不限层级**：源站分类按树形全部展示，一级、二级都能映射；本站目标也一级、二级都能选。影片入库时 `category_id` 取映射到的本站分类，`category_pid` 取该分类的父分类（目标为一级时父分类为 0）。
- **一对一**：一个源站分类只能映射到一个本站分类；多个源站分类可以映射到同一个本站分类。
- **批量**：可勾选多个源站分类一次映射到同一个本站分类。
- **修改映射只影响之后的采集**，已入库影片的分类不变。需要同步老数据时，在映射行点「按新映射重刷」，按影片当前 `category_id` 等于旧映射分类做批量更新，执行前提示将影响的行数。
- **本站分类删除**：有映射指向该分类时提示映射来源数量，确认删除则相关映射重置为 `status = 0`、`category_id = 0`。
- **源站分类消失**：重新获取分类时不再返回的记录保留不删，界面标记「源站已移除」。

## 5. 采集系统

### 5.1 采集流程

接口分工，`ac` 与 `pagesize` 由程序控制，不作为可配项：

| 用途 | 请求 |
|---|---|
| 采集影片 | `{api_url}?ac=videolist&pg={page}&pagesize={pagesize}&at={api_format}{&api_params}` |
| 获取分类 | `{api_url}?ac=list&at=json{&api_params}`，固定按 JSON 解析，见下 |
| 单片重采 | `{api_url}?ac=detail&ids={source_vod_id}&at={api_format}` |

- 采集必须用 `ac=videolist`。该动作一次请求返回整页全部字段，含封面、演员、简介与播放地址；改用 `ac=list` + 逐条 `ac=detail` 会使每页请求数变成「条数 + 1」。
- 获取分类必须用 `ac=list`，只有该动作的响应带 `class[]`，`ac=videolist` 不带。
- 获取分类固定按 JSON 解析，与源的 `api_format` 无关。`api_format=json` 的源直接请求 `at=json`；`api_format=xml` 的源按两种方式依次降级：先把地址里的 `/at/xml/` 换成 `/at/json/`，仍拿不到分类时改用查询参数 `at=json`。
- 获取分类不能按 XML 解析：XML 的 `class[]` 不含 `type_pid`，拿不到父子级。
- 采集与单片重采仍按源的 `api_format` 请求与解析。
- 接口地址里的 `/at/json/`、`/at/xml/` 片段与 `api_format` 必须一致，保存时校验并拒绝。
- `pagesize` 显式传值，不依赖接口默认值。

一次任务执行的步骤：

1. 取任务与源，取得该源的采集锁（同一时刻一个源只跑一个任务，不同源可并行）。
2. 写 `lcm_collect_log`，`status = 0`，`started_at = NOW()`。
3. 按页循环：
   1. 请求列表接口，取本页数据。
   2. 本页无数据则结束循环。
   3. 逐条处理：查分类映射（`ignored` / `skipped` 则计数跳过）→ 判重 → 写 `lcm_vod` → 写 `lcm_vod_play`。
   4. 提交本页事务。
   5. 写 `lcm_collect_log_detail` 一行，记录页码与五个计数。
   6. 累加 `lcm_collect_log` 的汇总计数。
   7. 检查取消标志，已取消则跳出循环。
4. 写 `finished_at` 与结束状态。

- 每页一个事务。事务边界与页对齐，中途中断不会留下半页数据。
- 采集记录明细一页一行，在事务提交后写入。

### 5.2 影片判重

判重键为「归一化名称 + 年份」。

归一化在入库前执行，数据库中存储的就是归一化后的名称：

| 规则 | 例子 |
|---|---|
| 去除首尾空格 | `" 流浪地球3 "` → `"流浪地球3"` |
| 全角字符转半角 | `"流浪地球３"` → `"流浪地球3"` |
| 连续空格合并为一个 | `"流浪 地球"` → `"流浪 地球"` |
| 括号与括号内内容保留 | `"流浪地球3(2027)"` 原样保留 |

年份匹配规则：年份相等，或任一方为 0，即视为命中。两侧年份都有值且不相等时视为不同影片。

判重之前先认源站身份：同一采集源内 `source_vod_id` 是不变的标识，本页任一条目的 `(source_id, source_vod_id)` 若已存在于 `lcm_vod_play`，直接复用其 `vod_id`，不再按名称年份判断。这样源站改标题（例如往片名里插一个点）、改年份时，只会更新那条影片，不会新增一条重复记录。名称年份规则只用于「这个源第一次出现的影片」。
年份取值：只用源站的 `vod_year`，为空就存 0，视为「未知年份」，不从别处推断，也不是错误。

- 名称相同、年份匹配到多条时，取 `id` 最小的一条。
- 后台编辑影片时，名称同样按上述规则归一化后保存（新增影片只有采集一个入口，后台不提供新建）。

查重按页分两步批量执行：先用本页全部 `source_vod_id` 查一次 `SELECT vod_id, source_vod_id FROM lcm_vod_play WHERE source_id = ? AND source_vod_id IN (...)`；再对剩下的条目取本页全部名称，算出各自的 `name_hash`，一次 `SELECT id, name, year FROM lcm_vod WHERE name_hash IN (...)`，在内存中按年份规则逐条判定，不对每条单独查库。

```sql
KEY `idx_name_hash` (`name_hash`)
```

- `name_hash = md5(归一化名称)`，不含年份。年份作为独立字段参与内存比较，使「任一方为 0 即命中」的规则可行。
- 归一化与哈希由程序计算，`name` 与 `name_hash` 必须同步写入，统一定义在 `packages/shared/src/vod.ts` 的 `normalizeName()` 与 `nameHash()`。
- 不加唯一约束。
- 同一 `name_hash` 的「查重 + 写库」在进程内串行执行：以 `name_hash` 为键加进程内互斥锁，不同采集源并行采到同一部影片时，后到的任务等待前一个写完再查库，避免重复建片。锁只覆盖查重与写库这一小段，网络请求不持锁。
- 互斥锁只在单进程内有效，与当前单实例部署一致。

### 5.3 多源线路合并

线路的唯一标识是 `(vod_id, source_id, source_from)`，三者相同即为同一条线路。不同源返回的 `source_from` 天然不同（如 `lzm3u8`、`ffm3u8`），同一部影片可并存多条线路。

采集一条影片的播放数据时，按下列规则处理：

| 情形 | 判定 | 动作 |
|---|---|---|
| 同键线路，新集数 ≥ 旧集数 | 新集数由 `play_url` 中 `#` 的个数算出 | 覆盖 `play_url` |
| 同键线路，新集数 < 旧集数 | 源站数据残缺 | 保留原值，不覆盖 |
| 无同键线路 | 新线路 | 插入新行 |
| 源站本次未返回的线路 | 与本条记录无关 | 保留不动 |
| `source_id = 0` 的手工线路 | 永不参与采集匹配 | 保留不动 |

- 集数计算：`play_url` 按 `#` 切分后取非空段数，空值视为 0 集。
- 线路顺序不按入库顺序，由全局配置 `line_order` 决定，见 6.2。
- 采集不删除任何线路。清理线路通过后台数据处理或删除采集源时一并删除该源线路（`source_id` 匹配的全删）。

写库按页批量执行：本页影片判重后取出全部 `vod_id`，一次 `SELECT id, vod_id, source_id, source_from, play_url FROM lcm_vod_play WHERE vod_id IN (...)`，在内存中按唯一键建索引逐条判定，再批量执行 `INSERT` 与 `UPDATE`。

### 5.4 增量与字段覆盖

采集范围由任务的 `range_type` 决定，通过接口的 `h` 参数实现：

| `range_type` | `h` 参数 | 含义 |
|---|---|---|
| 1 | `h=24` | 本日更新 |
| 2 | `h=168` | 本周更新 |
| 3 | `h=720` | 本月更新 |
| 4 | 不传 | 全部 |

已入库的影片按 `vod_time` 判断是否需要更新：本条记录的 `vod_time` 与同源线路的 `source_updated_at` 相同时整条跳过，不写库。

更新已入库影片时的字段覆盖规则：

| 字段 | 处理 |
|---|---|
| 标题、副标题、封面、演员、导演、编剧、简介、详细介绍、备注、上映日期、地区、语言、年份、总集数 | 覆盖为源站的值 |
| 分类 `category_id`、`category_pid` | 保留不动 |
| 状态 `status` | 保留不动 |
| 线路 `lcm_vod_play` | 按 5.3 处理 |

原文入库，不做截断。字段长度按源站实测最大值留足余量（实测 3 万条样本）：标题 33、副标题 255、封面 86、演员 255、导演 255、编剧 75、简介 152、备注 15、上映日期 26、地区 4、语言 10、详细介绍 5512 字符。

采集不改变影片的上架状态；库中存在、但本次采集结果里没有的影片保持原状。

### 5.5 调度与限流

调度器每分钟触发一次，读取全部已启用的任务，逐个用 cron 表达式判断当前时间是否命中，命中则启动该任务。任务的增删改与启停即时生效，不需要重启服务。

`cron` 为 5 段式：`分 时 日 月 周`，按 Asia/Shanghai 解释，不支持秒级。

任务按采集源串行：同一采集源在同一时刻只运行一个任务，不同采集源之间可并行执行。任务到点触发时，若同源已有任务在执行，本次跳过，只写服务端进程日志（stdout），不写 `lcm_collect_log`。运行状态由进程内变量维护。

限流作用于单个采集源：每两次请求之间，从**上一次请求结束**开始计时，等待 `interval_sec` 秒后再发起下一次请求。单次请求耗时超过 `interval_sec` 时不额外等待，直接发起下一次。

### 5.6 失败与重试

请求超时、连接失败、HTTP 状态非 200、响应解析失败，均视为请求失败。失败后重试，最多重试 `lcm_collect_source.retry_times` 次，每次重试前按 `interval_sec` 等待，与正常请求的节奏一致。

页级失败：单页在重试耗尽后仍失败，该页作废并记入明细，继续下一页；连续 3 页失败则中止本次任务，`status = 2`，`message` 记录中止原因。

条级失败：单条影片的处理使用 savepoint 保护，出错时回滚该条，其余记录照常提交。

断点续采：每次成功处理一页后，把该页号写入 `lcm_collect_log.last_page`。失败（`status = 2`）或被取消（`status = 3`）的记录，若 `last_page` 尚未到达 `total_pages`，可以在采集记录列表点「续采」，从 `last_page + 1` 页继续。续采**续写同一条记录**：状态改回进行中、`finished_at` 清空、`resume_count` 加一、`interrupted_ms` 累加本次中断时长（用 `TIMESTAMPDIFF` 计算），明细继续追加、计数继续累加，因此进度条最终能到 100%。列表里的「耗时」是扣掉 `interrupted_ms` 的实际采集时长。源站列表是动态的，两次之间若有新增，页码会整体后移，边界上的少量影片本轮可能被跳过，由下一轮采集补齐。

计数口径：

| 情况 | 计入 |
|---|---|
| 源站分类被忽略 | `ignored` |
| 分类未映射 | `skipped` |
| 缺少 `vod_id`、缺少名称、写库报错 | `failed` |
| `play_url` 为空 | 正常入库，不计失败 |

### 5.7 下架与清理

删除采集源时，同时删除该源的全部线路（`source_id` 匹配的记录），`source_id = 0` 的手工线路保留。确认删除前提示受影响的数据量，删除后将失去全部线路的影片自动下架（`status = 0`）。

禁用采集源只停止采集，已有线路照常播放，不影响前台。

数据处理工具提供以下功能：

| 功能 | 说明 |
|---|---|
| 批量替换播放地址 | 按前缀替换 `play_url`，可选择只处理某个采集源 |
| 批量替换图片地址 | 按前缀替换 `lcm_vod.cover`，全站一起替换（封面存在影片上，不区分采集源） |
| 批量删除某源线路 | 按 `source_id` 清理 |
| 清理无线路影片 | 扫描并下架没有线路的影片 |

重复影片工具按片名哈希分组，列出可自动合并与疑似重复的组：

| 分组 | 判定 | 处理 |
|---|---|---|
| 可自动合并 | 严格键相同（去掉空白、保留标点）且年份一致或任一方为 0 | 一键合并或勾选合并 |
| 疑似重复 | 宽松键相同（再去掉标点）但严格键不同 | 逐组人工确认后合并 |
| 年份冲突 | 严格键相同但年份不同 | 不提供合并，视为不同作品 |

合并时保留线路最多的一条（并列取 id 最小），其余影片的线路并入保留影片，同一源同一线路标识重复时保留集数更多的那条，然后删除多余影片行。

## 6. 播放与内容

### 6.1 播放模式

按采集源配置决定。源上 `parse_url` 填了解析接口地址，播放页用 iframe 套解析页；未填写则用原生 `<video>` + hls.js 播放 m3u8。

### 6.2 线路顺序

- 全局配置项 `line_order`，存于 `lcm_setting`，值为线路标识（`source_from`）的逗号分隔序列，如 `lzm3u8,ffm3u8,tkm3u8`。
- 播放页按该序列排列线路；未列入的排在最后，同段内按 `lcm_vod_play.id` 升序。
- 默认选中排序后的第一条，不做浏览器本地记忆。

### 6.3 播放页地址

播放页 URL 编码「影片 + 线路 + 集数」三项信息：

```
/play/{vodId}/{playId}/{ep}
```

- `playId` 为 `lcm_vod_play.id`，永久不变。线路顺序调整不影响已分享的链接。
- `ep` 为剧集序号，从 1 开始。
- `/play/{vodId}` 不带线路与集数时，直接渲染第一条线路的第一集，不做跳转。
- 路径不带 `.html` 后缀。

剧集列表由服务端分页，每页 50 集。

剧集名称直接取源站返回的名称（`名称$地址` 中 `$` 前的部分）。名称缺失时用「第 N 集」兜底。

### 6.4 播放地址处理

线路来源的 `parse_url` 为空时直连播放：

| 播放地址 | 处理 |
|---|---|
| 含 `.m3u8` | 用 hls.js 播放 |
| 其余 | 直接交给播放器 |

直连播放固定使用 ArtPlayer（`themes/default/assets/vendor/artplayer.min.js`，本地托管，不依赖 CDN）。控制栏按钮由「播放设置」里的开关决定，设置变化立即生效。

两者都无法播放时，页面提示「该线路暂不支持在线播放」。

`parse_url` 非空时，播放页用 iframe 载入解析页。地址拼接规则：

| `parse_url` 内容 | 拼接结果 |
|---|---|
| 含 `{url}` 占位符 | 将 `{url}` 替换为 URL 编码后的播放地址 |
| 不含占位符 | `parse_url` 与播放地址直接相连，不做编码 |

播放器随主题发布，不使用 CDN：`themes/default/assets/vendor/hls.min.js`（hls.js 1.7.4）与 `themes/default/assets/vendor/artplayer.min.js`（ArtPlayer 5.4.0）。

hls.js 配置为 `{ enableWorker: true, lowLatencyMode: false, maxAudioFramesDrift: 5 }`：源站每 20 秒一个 discontinuity，拼接点音画长度不一致，`maxAudioFramesDrift` 给音频时间戳校正留出余量，避免频繁丢帧/补帧产生的电流声。

静态资源缓存：`vendor/`、`img/` 下带版本参数、内容不变，`max-age=2592000, immutable`；`app.js`、`style.css` 仍在改动，返回 `no-cache` 走协商缓存，避免升级后用户看到旧文件。

### 7.2 模板变量

渲染前统一注入公共变量，路由只传页面自己的变量：

| 公共变量 | 内容 |
|---|---|
| `site` | 站点名称、logo、统计代码、免责声明等 |
| `nav` | 导航分类树 |

| 页面 | 页面变量 |
|---|---|
| index | `vods`（最新 24 条） |
| list | `category`、`types`、`vods`、`pagination`、`filter`、`years` |
| detail | `vod`、`lines`、`episodes`、`current_line`、`pagination`、`page_numbers` |

| search | `keyword`、`vods`、`pagination` |

- 详情页点剧集跳到 `/play/{id}/{playId}/{ep}`；点线路跳到该线路第 1 集。
- 影片没有任何线路时，详情页不渲染线路与剧集区。

### 7.3 路由与 URL

| 页面 | URL |
|---|---|
| 首页 | `/` |
| 分类列表 | `/list/{alias}`、`/list/{alias}?page=N` |
| 详情 | `/detail/{id}`，线路 `?line={playId}`，剧集分页 `?ep={page}` |
| 播放 | `/play/{id}/{playId}/{ep}` |
| 搜索 | `/search?wd=关键词`，可选 `&year=2026`、`&sort=time|new`、翻页 `&page=N` |
| 静态资源 | `/assets/**` |
| 上传文件 | `/uploads/**` |

- 分类列表用 `alias`，详情与播放用 ID。URL 不带 `.html` 后缀，也不带结尾斜杠。
- 分页与筛选统一走查询参数：`/list/dianying?page=2&year=2026&sort=time`。
- 带筛选参数的列表页输出 `canonical`，指向无参数版本 `/list/dianying`。

列表页的查询参数：

| 参数 | 取值 | 默认 |
|---|---|---|
| `page` | 正整数 | 1 |
| `type` | 二级分类的 `alias` | 不筛选，显示全部类型 |
| `year` | 4 位年份 | 不筛选 |
| `sort` | `time` 最近更新、`new` 最新入库 | `time` |

- 分类页只有一级分类页面，二级分类没有独立 URL，作为 `type` 参数在一级分类页内筛选。
- 不带 `type`：按 `category_pid = {一级id} OR category_id = {一级id}` 取影片，映射到一级分类的影片也能出现在该分类页里。
- 带 `type`：按 `category_id = {二级id}` 取影片。
- 一级分类下没有子分类时，`type` 这一排筛选不显示。
- 搜索参数为 `wd`，翻页为 `page`。`wd` 长度 1–50 字，超出截断；`wd` 为空时渲染空结果页，不做跳转。
- 翻页越界返回 404；`page` 非数字或小于 1 按 1 处理。

间距刻度定义为 4 的倍数，只在 `:root` 中声明，页面样式一律引用变量，不再写字面量：

| `--space-3` | 12px | 行内间距 |
| `--space-4` | 16px | 常规间距、主块间距 |
| `--space-5` | 20px | 卡片内边距 |
| `--space-6` | 24px | 区块间距、页底留白 |
| `--space-7` | 32px | 大区块分隔 |

页面级语义变量：

| 变量 | 取值 | 用途 |
| --- | --- | --- |
| `--gap-block` | `--space-4` | 页面主块之间（面包屑→内容、卡片→卡片、区块→区块） |
| `--gap-grid-x` | `--space-4` | 卡片网格横向间距 |
| `--gap-grid-y` | `--space-4` | 卡片网格纵向间距 |
| `--pad-card` | `--space-5` | 卡片内边距 |

版式约定：

- 页面从上到下由若干「块」组成，块与块之间固定 `--gap-block`，不写各自的上下边距。
- 块内的标题与内容之间 16px；块内列表项、标签之间 4~8px。
- 面包屑只有下外边距（`--gap-block`），没有上外边距，顶端间距由它自身的上内边距提供。
- 卡片内边距统一 `--pad-card`；网格卡片行列间距分别取 `--gap-grid-y` 与 `--gap-grid-x`。
- 分页区域上间距 `--space-6`，下间距 `--space-2`，主容器底部留白 `--space-6`。
- 字号与颜色同样只引用变量（`--text`、`--text-2`、`--text-3`、`--primary`、`--line`），不写十六进制字面量。

字号层级，同样只在 `:root` 声明，样式引用变量：

| `--fs-small` | 13px | 辅助信息、面包屑、筛选、简介 |
| `--fs-body` | 14px | 正文、卡片标题、空状态 |
| `--fs-emphasis` | 15px | 主导航、主要按钮 |
| `--fs-title` | 18px | 区块标题 |
| `--fs-logo` | 20px | 站名 |
| `--fs-page-title` | 21px | 详情页片名 |
| `--fs-display` | 64px | 404 状态码 |

| 断点 | 调整 |

| `max-width: 1100px` | 播放页改为上下排列（播放器在上、选集在下） |
| `max-width: 900px` | 影片网格 → 4 列、剧集网格 → 5 列；详情页封面缩小、上下排列；导航改为横向滚动，不隐藏 |

卡片只有一种外观：白底、`--radius` 圆角、`--shadow` 阴影、`--pad-card` 内边距。首页区块用同一套规则，只是把背景、阴影、内边距清空（`.home .section`）。

空状态统一用 `.empty-tip`，文案句式统一为「暂无…」或「没有…，…」，不出现面向管理员的说法（如「先去后台采集」）。

## 8. API 设计

### 8.1 通用约定

所有后台接口前缀 `/api/admin`。

响应体统一结构：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

HTTP 状态码同时反映结果，`code` 非 0 表示业务错误，`msg` 为可直接展示的中文提示。

分页请求参数为 `page` 与 `page_size`，`page_size` 默认 20，上限 100，超出按 100 处理。分页响应：

```json
{
  "code": 0,
  "msg": "ok",
  "data": { "items": [], "total": 780, "page": 1, "page_size": 20 }
}
```

写操作只接受 `Content-Type: application/json`。登录态使用 `httpOnly` cookie，`SameSite=Lax`，不额外使用 CSRF token。

## 9. 安全与合规

### 9.1 登录防护

同一 IP 连续 5 次登录失败后锁定 15 分钟。失败计数保存在进程内存中，进程重启后清零。

登录失败统一提示「账号或密码错误」，不区分账号不存在与密码错误。

### 9.2 后台入口

后台固定挂载在 `/admin`，不做路径隐藏。

### 9.3 免责声明

前台页脚显示免责声明，内容在站点设置中配置。

## 10. 部署与运维

### 10.1 运行环境

生产环境后续确定，目标形态为 NAS 上的 Docker 部署。

环境变量统一放在仓库根的 `.env`，仓库内提供 `.env.example` 列出全部键：数据库地址、端口、库名、账号、密码、连接池上限、JWT 密钥、服务端口。

### 10.2 进程守护

使用 PM2 守护进程。

### 10.3 数据初始化

提供 `init.sql`，包含建表语句与初始数据（管理员账号、默认配置、初始分类），可直接导入数据库。后续结构变更使用 drizzle 迁移。

### 10.4 日志

日志输出到 stdout，由 PM2 收集，不自行实现轮转。
